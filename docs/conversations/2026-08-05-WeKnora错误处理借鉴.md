# WeKnora 错误处理借鉴

## 参考结论

参考目录为 `/Users/lsp/project/WeKnora`，仅用于设计借鉴，不修改参考项目。

- WeKnora 使用带上下文的结构化 logger，记录任务类型、任务 ID、知识库/文档 ID、重试次数和错误。
- Asynq 任务失败先按重试策略继续重试，耗尽重试次数后由 dead-letter middleware 写入 `task_dead_letters`，保存任务类型、范围、原始错误和失败次数。
- 运行时任务 Inspector 支持查看队列状态和失败任务，并能手动重新执行；业务状态由 dead-letter callback 同步为 failed。
- HTTP 客户端保留非 2xx 响应正文，并使用类型化 APIError 暴露状态码、正文和业务错误码。

## 对 n2sql-agent 的借鉴边界

- 当前项目只需要 PostgreSQL + pgvector 和单进程 worker，不引入 Redis/Asynq/Langfuse。
- 第一阶段优先增加 Worker 后端结构化日志，以及模型上游错误正文的有界保留。
- 现有 `document_processing_tasks.error_message` 已可作为轻量 dead-letter 记录；后续再增加安全的重试入口。
- 不记录 API Key、完整文档内容或完整请求体。

## 当前落地

- Worker 文档处理失败时直接打印 `task_id`、`document_id` 和截断后的错误信息到后端终端。
- 失败信息仍然写入 `document_processing_tasks.error_message`。
- 暂不增加前端错误展示、自动重试、Redis/Asynq 或 dead-letter 队列。
