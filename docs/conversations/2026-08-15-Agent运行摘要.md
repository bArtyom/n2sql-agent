# Agent 运行摘要

## 背景

工具轨迹记录了“调用了哪些工具、返回了什么摘要”，但如果只看事件列表，不容易快速判断本次运行用了多少步骤、调用了多少次模型、花了多少 Token 和时间。

## 实现链路

1. `internal/agent.AgentRun.Stats()` 在一次运行结束时生成 `RunStats`。
2. Handler 在保存会话时，把安全的计数和耗时字段映射为 `conversation.AgentTraceStats`。
3. `AgentTraceStats` 放在已有 `conversation_messages.metadata.agent_trace.stats` JSONB 中，不新增表和迁移。
4. SSE 的 `run_finished` 事件直接携带同一份 stats；前端实时回答读取它。
5. 历史消息读取 `agent_trace.stats`；前端用相同格式恢复摘要。

## 保存内容

- 步骤数、模型调用数、工具调用数和成功/失败工具数。
- Prompt、Completion、Embedding、Total Token 数。
- 总耗时和失败分类。

不保存模型思考过程、原始工具结果、API Key 或完整提示词。

## 前端兼容

前端对历史 metadata 和 SSE payload 做运行时校验：只接受对象、有限非负整数，并限制数值上限。旧消息没有 `stats` 时继续显示事件数量，不影响历史记录。

## 学习要点

运行事件回答“过程中发生了什么”，运行摘要回答“这一轮总体用了多少资源、是否成功”。二者放在同一条 Agent trace 下，既能展开排查，也能先看汇总。
