# RAG 学习记录

## 背景

用户按“一次一道题、五题后总结考核”的方式学习 Agent/RAG 面试题，目前进入 RAG 模块。

## 已确认内容

- RAG 的核心是检索、增强、生成。
- 完整流程包括离线文档解析、清洗、切分、向量化、入库，以及在线问题处理、检索、上下文组装和模型生成。
- RAG 适合私有知识、实时知识和需要引用溯源的场景；微调更适合固定行为、格式和领域任务能力。
- Chunk 太大可能引入噪声并浪费上下文，太小可能破坏语义；切分时要考虑文档结构、Token 长度、Overlap 和元数据。
- Embedding 将文档和用户问题转换成向量，用于语义检索；模型选择要考虑语言/领域适配、检索效果、Recall@K、延迟、成本、维度、输入长度和隐私。

## BM25 延伸

- BM25 是基于关键词匹配的经典检索算法，不理解深层语义。
- 核心考虑词频 TF、逆文档频率 IDF 和文档长度归一化。
- 词出现越多，相关性通常越高，但重复到一定程度后收益递减。
- 越稀有的词权重越高，常见词权重越低。
- 长文档需要长度归一化，避免仅因为篇幅长就获得高分。
- BM25 与向量检索结合，可以兼顾精确关键词匹配和语义匹配。

## 下一小节

- 主题：RAG 系统的评估指标。
- 重点：区分检索阶段指标与生成阶段指标。

## RAG 评估第 1 题讲解要点

- 检索阶段：Recall@K/Hit@K 判断相关文档是否被召回，Precision@K 判断召回结果中相关文档的比例，MRR/nDCG 关注相关文档的排序位置和质量。
- 生成阶段：关注答案正确性、相关性、完整性、忠实度/有据性和引用准确性。
- 评估不能只看最终答案，需要定位是召回失败还是生成失败；还可以结合人工评估、固定评测集和线上延迟/成本指标。
