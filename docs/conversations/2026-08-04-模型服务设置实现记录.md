# 2026-08-04 模型服务设置实现记录

## 背景

第一阶段前端工作台已经可以创建知识库、上传 Markdown/TXT、查看处理状态并进行 SSE 问答。下一步需要把已经存在的模型 Provider 配置接口接入工作台，方便本地开发时查看和更新模型服务配置。

## 已确认结论

- `n2sql-agent` 是独立实现目录，WeKnora 只作为交互和工程形态参考。
- 当前阶段只做通用文档知识库问答，不引入 N2SQL 或 schema 相关内容。
- API Key 继续只放在后端 `.env` 中；浏览器不能输入、显示或保存真实密钥。

## 本次实现

- 在工作台左侧底部增加“模型服务设置”入口。
- 点击后打开右侧“模型控制台”抽屉，读取 `GET /api/model-provider`。
- 没有已保存 Provider 时使用兼容 OpenAI API 的空白默认值；其他 API 错误会在抽屉内显示。
- 没有已保存 Provider 时，后端只返回当前配置的环境变量名（不返回密钥），前端据此兼容自定义的 `MODEL_PROVIDER_API_KEY_ENV_VAR`。
- 保存时调用 `PUT /api/model-provider`，仅提交服务名称、Base URL、聊天模型和嵌入模型，并固定使用 `OPENAI_API_KEY` 作为后端环境变量名。
- “测试连接”调用 `POST /api/model-provider/connection-test`。后端从 `.env` 读取密钥并请求 `/models`，前端只展示成功或错误状态。
- 抽屉使用现有工作台的深色导航、米白内容和琥珀强调色；移动端会切换为全宽面板。

## 验证结果

- `npm run build` 通过，包含 `vue-tsc --noEmit` 和 Vite 生产构建。
- 已在本地浏览器打开设置抽屉，确认入口、表单字段、密钥安全提示和操作按钮可见。
- 浏览器验证时后端已停止，因此读取配置显示预期的 HTTP 500；启动后端和数据库后即可继续验证真实读写。
