# Agent 与 RAG 答案反馈闭环

## 背景

Agent/RAG 已经能够展示引用、检索统计和运行轨迹，但还缺少用户对最终答案质量的显式反馈。先实现最小的二值反馈，不引入复杂评价表单或自动奖励模型。

## 接口契约

```http
POST /api/knowledge-bases/{knowledgeBaseID}/conversations/{conversationID}/messages/{messageID}/feedback
```

请求：

```json
{"rating": 1}
```

`1` 表示有帮助，`-1` 表示需要改进。相同管理员对同一条 assistant 消息重复提交时执行更新，不产生重复记录。

## 实现要点

- 使用 `conversation_message_feedback` 表保存管理员、会话、消息和评分。
- SQL 同时校验知识库归属、会话归属、消息属于该会话且角色为 `assistant`。
- 前端只对有消息 ID 的历史 assistant 消息显示反馈按钮，避免对尚未持久化的流式占位消息提交反馈。
- 流式回答保存成功后，`conversation_saved` 事件返回 `assistant_message_id`，前端立即补齐消息 ID 并显示反馈按钮。
- 反馈接口是独立子资源，不污染回答正文和 Agent trace metadata。

## 面试表达

用户反馈不是直接修改回答，而是建立“回答消息 → 用户评价”的旁路关系。这样既保留原始回答，又可以按知识库、模型、检索统计和 Agent trace 聚合质量数据，为后续离线评估提供样本。

## 当前限制

本轮只保存二值评分，暂不做原因标签、文字评论、自动重试或模型奖励。后续可以基于反馈和检索统计构建小规模 RAG 评测集。

## 统计指标

新增 `GET /api/knowledge-bases/{knowledgeBaseID}/feedback/stats`，按当前管理员和知识库聚合反馈总数、正负反馈数和满意率。前端在聊天区域展示当前知识库满意率。

## 动态起步问题

起步问题先采用前端基于已完成文档标题的确定性生成：未选择文档时展示知识库级问题，选择文档后切换为针对选中文档的问题。这样不额外消耗模型调用，也不会因为推荐问题生成失败阻塞 Agent/RAG 主链路；后续如果需要再增加模型生成版本。
