# 可控思考与聊天附件实现记录

## 背景

用户希望在已有 `reasoning_content` 展示之后继续实现真正可控的思考级别，并完成聊天附件/图片能力。

## 已确认结论

- 思考级别提供 `fast`、`standard`、`deep` 三档；后端映射为 OpenAI-compatible `reasoning_effort=low/medium/high`。
- 空的旧请求不附带 `reasoning_effort`，保证原有 Provider 兼容；只有显式选择思考级别时才传参。
- 附件只属于当前一轮标准 Agent 请求，不自动写入知识库，不写入会话历史，不落盘。
- 支持 PNG/JPEG/WEBP 图片、TXT/Markdown 文本；最多 3 个附件，单图 4MiB，单文本 128KiB。
- 服务端校验文件名、MIME、base64、UTF-8 和图片魔数；图片转成 data URL，多模态 content parts 发送给模型，文本附件转成 text part。
- Research/A2A 暂不接受附件和思考级别。

## 实现结果

- `modelclient.ChatMessage` 保持普通文本消息的字符串 content 形状，新增 `ContentParts` 仅在多模态消息时序列化为数组。
- `modelruntime` 使用 context 传递 reasoning effort，避免破坏既有 Agent runner 接口。
- `agentservice` 负责思考级别与附件业务校验及消息转换。
- Handler 扩大有界请求体限制，并把思考级别/附件纳入幂等请求哈希。
- Vue 输入区增加思考选择器、附件选择、图片缩略图、文本附件卡片和删除操作。

- 本地前端页面加载成功，控制台无 error/warn；后端和 Docker/Postgres 未启动，未完成真实附件发送链路。
