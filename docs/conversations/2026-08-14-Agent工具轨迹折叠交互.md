# Agent 工具轨迹折叠交互

## 背景

当前后端已经在 `conversation_messages.metadata.agent_trace.events` 中保存有界的工具名称、参数预览和结果摘要。前端此前把这些信息全部直接展开，长参数会干扰用户阅读答案。

## 已确认结论

- 参考 WeKnora 的交互：工具轨迹默认只显示一行摘要，用户点击箭头后再查看详情。
- 本轮只修改前端，不新增后端接口、数据库字段或原始工具结果保存。
- 可展开内容为现有的参数预览和结果摘要；原始工具结果仍通过引用卡片查看。

## 本轮实现

- `ChatMessage.expandedAgentEvents` 保存当前页面的展开状态，属于 UI 状态，不会发送给后端。
- `agentTraceKey` 优先使用 `tool_call_id`，没有 ID 时使用事件类型、步骤和列表位置组合，保证每行可以独立展开。
- 工具调用事件显示键盘可操作的箭头按钮，默认 `aria-expanded=false`；点击后切换当前事件的参数和结果摘要。
- 非工具事件保留固定占位符，保持轨迹各行的对齐；重新生成回答时清空旧的展开状态。

## 验证

- `npm run build` 通过。
- 浏览器冒烟验证：历史 Agent 轨迹默认显示“展开工具详情”，点击后显示 `参数：...`；再次点击可收起。
- 浏览器控制台没有出现前端错误。

## 后续

- 如果需要更接近 WeKnora，可再增加整个“Agent 运行轨迹”面板的总开关。
- “每个工具对应哪些引用”和安全的结构化结果预览需要后端把引用索引与工具事件关联起来，暂不在本轮扩展。
