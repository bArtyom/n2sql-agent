# 岗位匹配与学习计划

## 背景

用户准备寻找后端实习与 AI Agent 平台开发相关岗位，提供了两类岗位要求：

- 后端实习：高并发/高可靠、计算机基础与算法、MySQL、Redis、消息队列、工程质量与协作。
- AI Agent 平台开发：Agent 框架、Multi-Agent、任务调度、工具调用、MCP、A2A、Function Call、ReAct/PlanAct/CodeAct、异步与分布式系统。

## 当前项目判断

`n2sql-agent` 当前定位为 Go 实现的生产化 RAG 后端底座，已完成知识库、文件上传、异步文档处理、Embedding、pgvector 检索、普通与 SSE 流式问答、模型 Provider 配置、PDF 提取与可选 OCR，并有较完整的单元测试。

当前项目对后端实习要求具备较好的工程基础，但尚未覆盖 MySQL、Redis、独立消息队列、压测/指标/链路追踪和算法训练证据。对 Agent 平台岗位，当前主要覆盖模型调用与 RAG，尚未覆盖 Agent Loop、工具注册与 Function Call、规划/反思、Memory、Multi-Agent、MCP/A2A。

## 初步学习结论

- 继续以本项目作为主项目，不另起孤立 Demo。
- 先补后端工程能力，再在现有 RAG 链路上扩展 Agent runtime。
- Go 作为主语言；重点学习 CloudWeGo Eino，并阅读 LangGraph 作为状态编排对照，不需要同时掌握所有框架。
- 主要工程切片：生产化中间件与可观测性、Redis、消息队列适配、单 Agent ReAct、工具/Function Call、短期记忆与上下文预算、Supervisor + 专业 Agent、MCP Server、A2A 适配、评测和压测。
- 面试准备与项目同步进行：Go/OS/网络/数据库/Redis/MQ/系统设计/算法每日小量积累，并形成项目取舍与指标话术。

## 待确认

- 后续优先投后端实习，还是把 AI Agent 平台岗作为同等优先目标。
- 每周可稳定投入的学习与开发时间。
- 是否继续使用当前 Go 1.22 环境，还是为后续 A2A Go SDK 升级到所需 Go 版本。

## WeKnora 参考项目评估

WeKnora 比当前项目更接近 Agent 平台岗位：已具备 ReAct Agent Engine、Function Calling、工具注册与并行调用、上下文压缩与 Memory、MCP、Skills 沙箱、Redis + Asynq 任务队列、Worker 池、限流、Langfuse 追踪、RBAC 和审计等能力。

但 WeKnora 仍不能替代完整学习：代码中未发现明确的 A2A 协议实现，已有 Custom Agent 不等于 Multi-Agent 协作；算法、MySQL/InnoDB、系统设计需要额外准备。只运行项目约等于熟悉产品，必须阅读、修改、测试并能解释核心模块，才能形成面试能力。

推荐组合：从 WeKnora 学生产级架构和 Agent 平台设计，在 n2sql-agent 中独立实现简化版 Agent Loop、工具调用、MCP/A2A 和可观测性，形成能自己讲清楚的作品。

## 本次计划调整

- 第一阶段知识库问答闭环视为完成；OCR 只做一次可选的真实扫描 PDF 验收，不再作为主线阻塞项。
- 新增第二阶段：先补 Redis、任务队列、重试/死信、Worker 可靠性、限流、指标、pprof 和压测，再实现 Agent Runtime。
- Agent 开发顺序调整为 Tool/Registry → Function Calling → ReAct → 上下文/记忆/安全 → 进程内 Multi-Agent → MCP → 最小 A2A。
- 新增八周学习与面试计划，按项目开发 50%、后端/计算机基础 30%、算法与面试表达 20% 分配时间。
- 明确不投入全量 OCR、复杂业务接入和多个 Agent 框架并行学习；每个 WeKnora 重点模块都要在 n2sql-agent 中完成一个缩小版、测试失败路径并形成面试说明。
