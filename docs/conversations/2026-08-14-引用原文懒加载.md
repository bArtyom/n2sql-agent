# 引用原文懒加载

## 背景

历史消息中的引用需要能长期展示，但不能把整段父块和子块原文无限复制进会话 metadata。此次把“保存有界预览”和“按需读取完整原文”拆开。

## 已完成

- `documentchunk.Reader` 增加 `Read(ctx, knowledgeBaseID, documentID, position)`。
- PostgreSQL 读取 chunk 时同时校验知识库归属和当前管理员，避免只凭 URL 中的文档 ID 越权读取。
- 新增 `GET /api/knowledge-bases/{id}/documents/{documentID}/chunks/{position}`，只返回引用详情需要的字段，不把检索分数重置为零。
- 前端点击被截断的引用后才请求完整内容；加载完成后同步当前抽屉和消息中的同一引用，保留原来的 match、fusion、rerank 等分数。
- 旧 chunk 没有父块时仍可正常返回，存在父块时同时返回父块内容。

## 调用链

`source card click` → `openSource` → `GET chunk detail` → `documentchunk.PostgresStore.Read` → `document_chunk + document + knowledge_base` 权限条件 → 前端合并详情 → 引用抽屉展示。

## 验证与限制

- 已运行 `go test ./internal/documentchunk ./internal/handler ./internal/app`。
- 还需运行前端 `npm run build` 和浏览器加载验证；真实点击读取需要数据库中存在可访问的引用。
- 当前接口按 chunk 位置读取，不返回原始文件下载；后续若需要文件级预览，再单独设计文档权限和分页。
