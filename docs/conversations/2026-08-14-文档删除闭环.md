# 文档删除闭环

## 背景

文档已经支持上传、异步处理、父子 chunk 和检索，但删除入口缺失。数据库记录删除后，原始上传文件也需要清理，否则会留下磁盘孤儿文件。

## 已完成

- `document.Service.Delete` 通过可选 `DeleteStore` 删除文档，并通过 `CacheInvalidator` 清理知识库检索缓存。
- PostgreSQL 删除只允许当前管理员名下、指定知识库中的文档；事务会锁定文档和最新处理任务。
- `pending`/`processing` 文档返回冲突，避免和 Worker 同时读写；终态文档删除时依赖数据库级联清理任务、子块和父块。
- 原始文件使用 `context.WithoutCancel` 尽力清理；文件清理失败只记录结构化错误，应用中的文档仍视为已删除。
- 新增 `DELETE /api/knowledge-bases/{id}/documents/{documentID}`，前端增加确认删除、列表刷新、文档筛选和引用状态清理。

## 验证

- `go test ./internal/document ./internal/handler ./internal/app`
- `npm run build`
- 浏览器打开本地工作台，确认两个已完成文档显示“删除”按钮且按钮可用；未实际点击，避免删除本地资料。
- `curl -X DELETE .../documents/not-a-number` 返回 400，验证路由和输入校验。

## 注意事项

- 数据库删除和文件删除不是一个事务；后续如果需要强一致，可增加待清理文件队列或后台清理任务。
- 当前拒绝删除处理中任务，没有增加“取消 Worker”接口。
- HNSW 索引会随 `document_chunks` 的级联删除自动维护，不需要单独删除索引节点。
