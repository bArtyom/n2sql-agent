# SSE 断线重连与面试回答

日期：2026-08-27

## 用户问题

如果前端通过 `run_id` 订阅 SSE，读到一部分事件后断线，Redis 又找不到 `Last-Event-ID` 对应的事件，并且 Agent 还没有完成，后端返回什么？面试官问“什么是 SSE、项目中怎么使用”时应该怎么回答？

## 核心知识

SSE（Server-Sent Events）是基于 HTTP 的服务器单向推送协议。浏览器建立 `text/event-stream` 长连接，服务器持续发送带有 `id`、`event` 和 `data` 的事件。它只负责服务器到浏览器的推送，提交任务、停止任务等操作仍然使用普通 HTTP 请求。

本项目的异步链路是：

```text
POST 提交问题
  ↓
创建 agent_runs，状态为 pending，返回 run_id
  ↓
前端 GET /agent-runs/{runID}/stream
  ↓
Worker 领取并执行 Agent + RAG
  ↓
事件先写入 Redis Stream/EventStore，再发布到 Hub
  ↓
SSE Handler 按 run_id 转发给浏览器
  ↓
最终答案和 Run 状态写入 PostgreSQL
```

Hub 是当前进程内的实时广播路径，Redis Stream 是短期事件回放路径。浏览器断线重连时携带：

```http
Last-Event-ID: event-3
```

后端先尝试从 Hub 恢复 `event-3` 之后的事件；Hub 不存在或游标过期时，再从 Redis/EventStore 恢复。如果找到 `event-3`，就补发 `event-4`、`event-5`，然后继续监听新事件。

## gap 但任务还没完成

假设前端已经收到 `event-3`，但 `event-3` 在 Hub 和 Redis 中都过期了，此时 Agent 仍然是 `running`：

```text
前端 → Last-Event-ID: event-3
后端 → event: gap
       data: {
         "code": "stream_replay_gap",
         "run_id": "run-42",
         "requested_event_id": "event-3",
         "recovery": "reload_durable_state"
       }
```

这不等于 Agent 执行失败。SSE Handler 关闭当前连接，前端随后查询：

```http
GET /api/knowledge-bases/7/agent-runs/run-42
```

如果返回：

```json
{
  "run_id": "run-42",
  "status": "running",
  "attempt_count": 1
}
```

前端应显示“中间过程部分丢失，任务仍在执行”，然后继续轮询状态或重新订阅。不能因为中间事件丢失就重新创建任务，否则可能造成重复模型调用和重复工具执行。

如果最终状态是 `succeeded`，就读取数据库中的 `response.answer`；如果是 `failed` 或 `canceled`，就读取错误原因或取消原因。也就是说：

```text
事件 gap = 中间展示过程缺失
Agent failed = Agent 本身执行失败
```

## 面试标准答案

> SSE 是基于 HTTP 的服务器单向推送协议，浏览器建立 `text/event-stream` 长连接，服务器持续发送带有事件 ID、事件类型和 JSON 数据的消息。我的 Agent + RAG 项目中，用户先通过 POST 创建 `agent_run`，后端立即返回 `run_id`，后台 Worker 再异步执行 Agent。Worker 产生 `run_started`、工具调用、工具结果、回答增量和结束事件，Hub 负责同进程内实时广播，Redis Stream 或 EventStore 负责短期回放，SSE Handler 根据 `run_id` 把事件转发给前端，最终答案和任务状态写入 PostgreSQL。浏览器断线重连时通过 `Last-Event-ID` 请求后续事件；如果事件仍在保留窗口中就补发，如果事件已过期则返回 `gap`，前端读取持久化 Run 状态。即使 SSE 断开，也不会导致后台 Agent 任务停止。

## 一句话记忆

```text
SSE 负责推送，run_id 负责关联，Hub 负责实时，Redis 负责短期回放，PostgreSQL 负责最终事实。
```
