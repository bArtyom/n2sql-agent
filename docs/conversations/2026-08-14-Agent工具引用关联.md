# Agent 工具调用与引用关联

## 背景

此前回答消息有全局 `sources`，工具轨迹只有工具名、参数和结果摘要。用户能看到引用，但不知道某条引用由哪一次工具调用产生。

## 实现方式

不把完整引用重复写进每个工具事件，而是使用稳定索引：

```text
document_id:position
例如：11:2
```

调用链：

```text
Engine.tool_finished 的 sources
  → sourceCollector 汇总全局 Response.Sources
  → traceCollector 给当前 TraceEvent 写入 SourceKeys
  → Handler 只保存经过全局 sources 校验的 source_keys
  → 前端展开工具轨迹
  → 用 source_keys 从当前消息 sources 找到引用
  → 点击后复用既有 openSource 查看原文
```

## 边界

- 工具轨迹只保存索引，不重复保存原文，避免 metadata 膨胀。
- Handler 只接受同时存在于 `response.Sources` 的索引，过滤伪造或过期索引。
- 前端历史数据也会再次从消息 `sources` 查找，不直接信任轨迹里的索引。
- 没有引用的工具（例如 `document_list`、`document_info`）仍只显示结果摘要，不显示空的引用区域。
- 旧消息没有 `source_keys` 时继续正常展示全局引用，保持向后兼容。

## 前端表现

工具轨迹默认折叠；展开后显示“本次引用”的文件名和段落位置，点击引用复用已有懒加载原文面板。
