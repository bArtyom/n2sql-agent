# Agent 工具失败安全降级

## 背景

标准 Agent 调用 `knowledge_search`、`document_list` 或 `document_info` 时，如果工具访问数据库、模型或上游服务失败，不能把底层错误细节直接通过 SSE 发给浏览器，也不能让模型在没有证据时继续猜测。

## 已确认结论

- 工具失败继续采用 fail-closed：本轮 Agent 标记失败，不生成无证据回答。
- 后端函数仍返回原始包装错误，便于日志和排查。
- `run_failed`、`run_canceled` 事件对外只发送按失败类别选择的固定提示。
- 前端继续复用已有 `run_failed` 事件，不需要新增接口或数据库字段。

## 实现链路

```text
Tool.Call 返回错误
  → Engine 标记 FailureTool
  → AgentRun 记录内部错误和失败状态
  → SSE 事件只携带固定中文提示
  → 前端显示安全提示并保留“重新生成”入口
```

当前固定提示包括：

- 工具失败：`知识库工具暂时不可用，无法可靠回答。`
- 模型失败：`模型服务暂时不可用，请稍后重试。`
- 超时：`请求处理超时，请稍后重试。`
- 步骤超限：`本次处理步骤过多，已安全停止。`

## 需要注意

- 系统提示词不是安全边界；错误脱敏必须在事件生成代码中完成。
- 不要为了“给模型一次机会”把工具错误原文放回上下文，否则可能泄露内部信息。
- 失败类别可以用于统计和排查，但用户提示应保持固定、短小，不包含 provider 响应、SQL 或连接信息。

## 验证

- `go test ./internal/agentruntime ./internal/agentservice ./internal/handler` 通过。
- `go vet ./internal/agentruntime ./internal/agentservice ./internal/handler` 通过。
- 回归测试确认工具错误和模型错误不会出现在公开 SSE 错误字段中。
