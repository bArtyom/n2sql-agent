# RAG 检索范围控制

## 背景

知识库搜索已经支持 1—20 条结果，但标准 Agent 的请求没有把用户想要的召回范围传到工具边界。用户希望继续完善可见的 RAG 功能，而不是先增加测试套件。

## 本轮完成

- 前端问答台增加“召回片段数”选择器：3、5、8、12、20。
- 标准 Agent 请求发送 `top_k`；协作研究沿用 `topK`；A2A 创建任务发送 `top_k`。
- `agentservice.ChatRequest` 增加 `TopK`，默认 5。
- Agent Handler 校验 `top_k`，拒绝 1—20 之外的值。
- Agent Service 创建带 `maxResults` 的知识库搜索工具。
- scoped tool 在执行时把模型超过用户上限的 `limit` 收窄，默认工具仍保持原有 20 条边界。
- 幂等请求 hash 包含 `top_k`，同一消息但不同检索范围不会错误重放旧答案。

## 调用链

前端选择 8 → `agent-chat/stream` / `multi-agent-chat/stream` / `/api/a2a/tasks` → Handler 解码校验 → Service/Supervisor 接收 topK → scoped `knowledge_search` 限制检索条数 → 引用结果返回前端。

## 验证

- `go test ./internal/agent ./internal/agentservice ./internal/handler ./internal/multiagent ./internal/a2a` 通过。
- `npm run build` 通过。
- 仍需在 Docker 和真实模型服务启动后做一次真实检索效果对比；本轮不扩写评测套件。
