# 启动方案

## 背景

项目从空仓库开始，第一阶段目标是先建立可运行、可扩展的 NL2SQL 通用工程底座，不提前实现复杂业务能力。

## 已确认结论

- 先完成工程骨架和 Schema 知识库基础能力。
- 后续再逐步实现自然语言生成、校验和执行 SQL 的业务核心。
- 本地工作资料统一保存在 `docs/conversations/`，不提交到 Git。

## 当前进度

- 已完成：项目说明、开发约定、Git 忽略规则、第一阶段的简要计划，以及最小 Go 服务骨架。
- 已实现：`GET /health` 返回 `200` 和 `{"status":"ok"}`；服务地址可通过 `SERVER_ADDRESS` 配置，默认使用 `:8080`。
- 已完成：安装 Go 1.26.5（官方发布包，已校验 SHA-256），命令位于 `/usr/local/go/bin/` 并通过 `/usr/local/bin` 可直接调用。
- 验证：`go test ./...` 全部通过；服务启动后 `GET /health` 返回 `{"status":"ok"}`。
- 已完成：补充 Git 工作流约定，要求每个可验证的小任务独立提交，并为较大功能使用功能分支。
- 已提交：初始化成果已提交为 `15ee7b8`（`chore: initialize Go service skeleton`）。
- 已调研：WeKnora 前端采用 Vue 3、TypeScript、Vite 与 TDesign；官方以 Docker Compose 组织本地服务。
- 已完成：安装 Docker 26.1.3、Docker Compose 2.27.1 和 Node.js 22.23.1。
- 当前阻塞：本环境运行在受限容器内，缺少 Overlay 挂载、iptables/NAT 和 IP 转发权限，导致 Docker 守护进程无法启动，故暂不能运行 Compose 服务。

## 下一步

1. 安装 Go 后，运行格式化与单元测试，并启动服务验证健康检查接口。
2. 增加基础日志和应用目录结构的下一层模块。
3. 接入 SQLite，建立 Schema 同步的最小闭环。
