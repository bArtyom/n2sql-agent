# 邻近 chunk 上下文扩展

## 背景

检索结果已经经过向量召回、关键词召回、RRF 融合和可选 Rerank，但单个 chunk 可能缺少前后语义。参考 WeKnora 的上下文扩展思路，本轮先实现最小的邻近 chunk 扩展，不引入父块表或新的数据库迁移。

## 已完成

- `documentchunk.SearchResult` 增加 `contextBefore` 和 `contextAfter`，不改变原始命中 chunk 的分数和位置。
- PostgreSQL 增加 `SearchNeighbors`，按知识库、文档和位置读取同一文档的邻近 chunk，默认前后各 1 块。
- retrieval 层通过可选 `NeighborSearcher` 接口调用扩展；旧的自定义 Store 不实现该接口时仍保持原行为。
- RAG prompt 使用“前置上下文 / 命中片段 / 后置上下文”格式。
- Agent 工具把扩展后的内容放入模型可读的 `content`，同时保留引用元数据。
- 前端引用详情和复制功能显示完整上下文。

## 调用链

用户请求 → Search Service → 向量/关键词/RRF/Rerank → `expandContext` → PostgreSQL `SearchNeighbors` → RAG 或 Agent prompt → 模型回答。

## 约束与注意事项

- 查询始终带 `knowledge_base_id`，避免跨知识库读取上下文。
- 扩展只读取前后各 1 块，暂未做父块、邻近多块配置和批量查询优化。
- 扩展失败会让本次检索失败并保留错误上下文；不支持扩展能力的旧 Store 则兼容降级。
- 上下文会参与 prompt/tool result 字节上限，避免无限增加模型输入。
