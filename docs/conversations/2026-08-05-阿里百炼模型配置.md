# 阿里云百炼模型配置

## 背景

项目需要使用阿里云百炼的 `text-embedding-v4` 做文档向量化，使用 DeepSeek-V4 Flash 做知识库问答。

## 已确认结论

- Embedding 模型 ID：`text-embedding-v4`。
- 对话模型 ID：`deepseek-v4-flash`。模型 ID 使用连字符，不能写成 `deepseekv4flash`。
- Base URL 使用业务空间提供的 OpenAI 兼容地址：`https://<API Host>/compatible-mode/v1`。
- API Key 只放后端 `.env`，数据库只保存 API Key 环境变量名，不保存密钥本身。
- 当前 Go 客户端会在 Base URL 后拼接 `/models`、`/embeddings`、`/chat/completions`。
- 当前客户端不显式发送 `extra_body.enable_thinking`；DeepSeek-V4 Flash 默认支持思考模式，后续如需显式控制再扩展请求结构。

## 配置待办

```env
DASHSCOPE_API_KEY=替换为真实密钥
MODEL_PROVIDER_API_KEY_ENV_VAR=DASHSCOPE_API_KEY
MODEL_PROVIDER_ALLOWED_HOSTS=<API Host>
```

在前端模型设置中填写服务名、兼容 Base URL、`deepseek-v4-flash` 和 `text-embedding-v4`，保存后分别测试连接、Embedding 和聊天调用。

## 未确定事项

- 业务空间的 `/models` 接口是否对当前 API Host 开放，需要用真实密钥测试；如果连接测试失败，应继续测试 `/embeddings` 或 `/chat/completions`，再决定是否调整连接检查逻辑。
- 如果要展示或控制思考过程，需要确认 API 返回字段并单独设计是否向用户展示，不能默认把思考内容写入日志或数据库。
