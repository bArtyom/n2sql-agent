# Agent 工具轨迹持久化

## 背景

历史消息之前只能恢复 Agent 的步骤类型和工具名称。用户可以看到“调用过知识库工具”，但看不到调用参数和结果是否有资料。

## 实现

- Agent Engine 在 `tool_called` 事件中增加有界、脱敏后的参数预览。
- `tool_finished` 事件增加结果摘要，例如“返回 3 条资料”或“没有命中相关资料”，不把原始工具结果复制到轨迹。
- `agentservice` 用 `traceCollector` 将事件合并成工具调用记录，并限制最多 32 条、每段最多 512 字节。
- Handler 保存 `conversation.MessageMetadata.AgentTrace.Events`；旧的 `Steps` 字段继续保留兼容旧历史。
- 前端实时 SSE 和历史消息恢复共用 Agent 轨迹模型，展示工具参数和结果摘要；引用原文仍通过单独的懒加载接口查看。

## 调用链

`Engine.tool_called/tool_finished` → `traceCollector` → `Response.Trace` → `conversationMetadataFromAgentResponse` → `message.metadata.agent_trace.events` → `selectConversation/restoreAgentEvents` → 前端轨迹卡片。

## 边界

- 不保存模型思考过程，不保存完整工具 JSON，不让工具返回内容变成可执行指令。
- 参数经过密钥模式脱敏并限制长度；详细事实内容继续走 Sources 引用。
- 老消息没有 `events` 时，前端回退到原来的 `steps` 显示。
