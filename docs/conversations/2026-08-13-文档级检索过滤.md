# 文档级检索过滤

## 背景

混合检索已经能同时使用向量和关键词，但用户有时只想针对某几份资料提问。过滤条件必须同时进入两条召回路径，不能只在返回结果后再过滤，否则会浪费模型和数据库查询成本。

## 本轮实现

- 请求增加可选 `document_ids`，最多 100 个正整数；服务端会去重并排序。
- `retrieval.SearchOptions` 是统一过滤对象，普通 RAG、标准 Agent 和搜索接口复用它。
- PostgreSQL 向量查询和关键词查询都使用 `document_id = ANY($n::bigint[])`，并继续保留知识库 ID 条件。
- Agent 的 `knowledge_search` 工具保存请求级文档范围，模型不能绕过这个范围。
- 前端只对“已处理完成”的文档显示复选框；不勾选时仍检索整个知识库。

## 调用链

```text
前端选择文档
  → agent-chat/stream 或 chat 请求携带 document_ids
  → Handler 校验数量和 ID
  → Retrieval Service 规范化范围
  → vector + keyword SQL 同时过滤
  → merge / rerank / distance filter
  → Agent 或 RAG 生成答案
```

## 边界

文档 ID 仍受 `knowledge_base_id` 约束，因此即使客户端传入其他知识库的 ID，也不会返回跨知识库资料。研究模式和 A2A 暂时保持原有默认全库范围，后续若需要再把同一个 `SearchOptions` 扩展到它们。
