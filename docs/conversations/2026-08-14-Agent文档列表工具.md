# Agent 文档列表工具

## 背景

标准 Agent 原来只有 `knowledge_search`。它可以根据问题检索相关 chunk，但不能可靠回答“知识库里有哪些文档、文件状态如何”这类目录问题。MCP 已有文档列表能力，本轮将同一类只读能力接入标准 Agent。

## 已确认结论

- `knowledge_search` 继续负责“按问题找相关内容”。
- 新增 `document_list` 负责“列出当前知识库的文档元数据”。
- 新增 `document_info` 负责“根据已经获得的文档 ID 查询单个文档的详细元数据”。
- 工具只接受 `limit`，不接受知识库 ID；知识库范围由服务端创建工具时绑定。
- 不新增数据库表，复用现有 `document.Reader` 和文档权限边界。

## 实现链路

```text
agentservice.Service
  → 创建当前知识库范围的 ToolRegistry
  → 注册 knowledge_search + document_list + document_info
  → 模型从三个只读工具中选择
  → DocumentListTool 调用 document.Reader.List
  → 返回文件名、类型、大小和 processing_status
  → 进入现有 Agent ReAct/SSE/轨迹链路
```

结果是有界 JSON，最多返回 20 个文档，并受 Agent 工具结果字节上限约束；没有文档或结果过大时不会把原始文件内容放进上下文。`document_info` 也只返回元数据，不读取全文。

## 验证

- `go test ./internal/agent ./internal/agentservice ./cmd/server` 通过。
- `go vet ./internal/agent ./internal/agentservice ./cmd/server` 通过。
- 覆盖工具正常返回、模型尝试传入知识库 ID、底层文档读取失败三条路径。
- `document_info` 覆盖指定文档返回和不存在文档拒绝。

## 后续

- 暂不做文档删除、全文读取等写操作工具。
- 暂不做工具与引用的精确关联，保持工具结果只返回安全的文档元数据。

## 本轮学习要点

- 工具描述只负责引导模型选择工具，不能代替后端权限校验；知识库范围必须由后端创建工具时绑定。
- `document_info` 只返回元数据，内容问题仍使用 `knowledge_search`，避免把整篇文档塞进上下文。
- 当前实现复用 `Reader.List` 后在内存中按文档 ID 过滤，代码简单但数据量大时应改成带知识库范围的数据库 `GetByID` 查询。
- 工具参数、返回字段和结果大小都要有界；文件名、状态等文档字段属于外部数据，不能当作指令执行。
- 新增工具时要同时检查注册表 allowlist、Agent 系统提示、旧调用方兼容性和错误语义。
