# 2026-08-04 PDF 文本提取实现记录

## 背景

前端和上传接口已经接受 PDF，但 Worker 原先只支持 TXT 和 Markdown。PDF 任务会因此失败，无法进入文本块和向量索引。

## 已完成

- 在现有 `documentextractor.Extractor` 中加入 `application/pdf` 分支，保持 Worker 的 `TextExtractor` 接口不变。
- 校验 PDF 头和文件尾，限制读取大小，拒绝路径逃逸、损坏 PDF 和无文本 PDF。
- 支持常见 PDF 文本绘制指令：`Tj`、`TJ`，以及括号字符串中的转义字符和 UTF-16BE 文本。
- 支持 `/FlateDecode` 压缩内容流，并限制解压后的大小。
- 新增正常 PDF、压缩 PDF、`TJ` 文本数组、空 PDF 和损坏 PDF 测试。
- 前端上传入口现在接受 `.pdf`，上传提示明确为文本型 PDF。

## 当前边界

这不是 OCR 引擎；图片型扫描 PDF、复杂字体映射和部分高级 PDF 编码可能无法得到完整文本。后续需要根据真实资料评估专用解析库或 OCR 服务。

## 验证

- `go test ./...` 和 `go vet ./...` 通过。
- `npm run build` 通过；Vite 仍提示现有前端包体积较大，但构建成功。
- 启动本地 PostgreSQL、迁移和后端后，浏览器确认上传控件的 `accept` 为 `.md,.txt,.pdf`，页面显示“文本型 PDF”，控制台无错误；验证结束后已停止本地服务和数据库容器。
