# 三连切片实现记录：断流续传 / 历史消息分页 / 实时检索进度

> 日期：2026-08-15。切片：#9 断流续传、#8 历史消息游标分页、#6 实时 RAG 流水线进度（WeKnora 对照盘点剩余项）。

## #9 断流续传（刷新后恢复未完成回答）

- **方案**：后端零改动——复用进程内 Hub 的事件快照 + `GET /agent-runs/{runID}/stream` 重放路由。前端把未完成的标准 Agent 运行持久化到 localStorage（`n2sql-pending-agent-run`：knowledgeBaseId/runID/conversationId），刷新后据此重建占位消息并重连重放。
- **写入时机**：stream 请求拿到 `X-Agent-Run-ID` 后写入（仅标准 Agent 模式）；`run_finished`/`run_failed`/`run_canceled`/`error` 任一终态或问答流程结束后清除。
- **恢复**：`onMounted` 在会话加载后调用 `restorePendingAgentRun()`；Hub 快照在进程内保留约 10 分钟，恢复失败降级为普通错误消息（可重新生成）。
- **与 #1 停止生成的关系**：同一套 hub 机制——断流（不取消）由重放恢复，用户停止（取消）由 run_canceled 终态呈现。

## #8 历史消息游标分页

- **后端**：`GET /conversations/{id}/messages` 支持 `before_id` + `limit`（默认 50、上限 200），返回结构改为 `{messages, has_more}`（升序）。`PostgresStore.ListMessagesPage` 用 `id < before_id ORDER BY id DESC LIMIT limit+1` 内层倒序取最新一页再外层升序，多取 1 条判断 has_more；SQL 带管理员归属条件。Store 接口新增 `ListMessagesPage`，Service 新增 `MessagesPage`（归属校验）。
- **前端**：选择会话时加载最新一页（`limit=50`）；滚动到消息区顶部时用当前最早消息 id 作为游标加载更早一页并保持视口位置；顶部显示"正在加载更早的消息…"。复制会话为 Markdown 改为分页拉全量（`limit=200` 循环），保证导出完整。
- **兼容**：旧接口 `/messages` 无参仍返回最新一页（结构变为对象），前端与测试同步更新。

## #6 实时 RAG 流水线进度

- **后端**：`rag.Service.stream()` 在检索前后新增 `retrieval_started` / `retrieval_finished` SSE 事件（`retrieval_finished` 携带检索统计）；handler 事件白名单放行。普通 RAG 流式事件序列变为：`retrieval_started → retrieval_finished → sources → delta → done`。
- **前端**：Agent 轨迹头部新增 `agentTraceStatus` 实时徽标——检索工具进行中显示"正在检索知识库…"，完成后显示"搜索完成 · N 条引用"，回答结束（run_finished）后回落到 `agentTraceSummary` 运行摘要。
- **验证**：curl 确认普通 RAG 事件序列与统计；浏览器采样到徽标序列 `正在检索知识库… → 搜索完成 · 5 条引用`（模型二次检索场景）。
