# 关键词倒排索引

## 背景

原关键词 SQL 在查询时对每个 chunk 临时执行 `to_tsvector`，小数据量可用，但知识库增大后会重复分词和扫描文本。

## 本轮实现

- `document_chunks.content_search` 是由 `content` 生成的 STORED `tsvector` 列。
- `document_chunks_content_search_gin_idx` 为全文词项提供 GIN 倒排索引。
- `document_chunks_content_trgm_gin_idx` 为错误码、命令、型号和短语提供 `pg_trgm` 模糊匹配索引。
- `SearchKeyword` 查询使用 `content_search @@ plainto_tsquery(...)`，精确短语使用 `lower(content) LIKE '%...%'` 兜底。
- 排序仍保留完整短语优先，再按 `ts_rank_cd` 排序。

## HNSW 说明

pgvector 的 HNSW 索引需要固定维度，而当前 `embedding vector` 列为了兼容不同模型没有写死维度。本次迁移不自动创建 HNSW：如果数据库为空，或者以后换了 embedding 模型，迁移时都无法安全推断应该使用哪个维度。确定唯一 embedding 模型后，再添加固定维度的专用索引，避免索引看似创建成功、后续却无法覆盖新数据。

## 结果

文档写入时由数据库维护全文向量，查询时通过 GIN 快速定位候选 chunk；上层混合检索、Rerank、Agent 和 RAG 接口不变。
