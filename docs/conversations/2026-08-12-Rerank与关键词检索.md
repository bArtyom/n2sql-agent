# Rerank 与关键词检索

## 背景

当前系统已经有 pgvector 语义召回和 PostgreSQL 关键词召回。交错合并可以保证两路都有机会进入候选集，但不能判断候选片段对当前问题的精确相关性，因此增加独立的 rerank 阶段。

## 实现

调用链变为：

```text
向量召回 + 关键词召回
    ↓
按 document_id:position 去重
    ↓
候选集扩大到最多 20 条
    ↓
可选 qwen3-rerank 重排
    ↓
返回 topK
```

- `modelclient.HTTPClient.Rerank` 负责阿里百炼兼容接口的 HTTP、鉴权、响应校验和索引映射。
- `modelruntime.RerankService` 负责读取当前 Provider、环境变量 API Key 和 rerank 配置。
- `retrieval.Service` 只依赖 `retrieval.Reranker` 接口；未配置模型时直接保留混合召回结果。
- `SearchResult` 新增 `KeywordScore` 和 `RerankScore`，前端可继续展示来源并在后续增加分数解释。

## 关键词算法

关键词检索不再只有 `strpos`：

- `ts_rank_cd(to_tsvector('simple', content), plainto_tsquery('simple', query))` 计算词项相关性。
- 原文完整包含查询短语时增加精确命中优先级，适合命令、型号、错误码等内容。

## 配置

模型服务设置页面可填写可选的 Rerank Base URL 和模型，例如 `qwen3-rerank`。两项必须同时填写；留空则不会发起第二次模型请求，也不会影响已有检索。

## 限制

本轮没有把 rerank Key 放到浏览器，也没有新增文档业务表。真实模型调用会产生额外费用和延迟；当前只完成可运行接入，后续再根据真实数据调整候选数量、失败降级和分数阈值。
