# 会话引用与 Agent 轨迹恢复

## 背景

此前会话消息已经保存检索统计和查询改写状态，但引用卡片与 Agent 运行轨迹主要只存在当前页面内。重新打开历史会话后，用户只能看到回答正文和统计，无法恢复“引用了哪些片段、Agent 做过哪些步骤”。

## 已确认结论

- 参考 WeKnora 的持久化引用和 Agent history 思路，但只实现当前项目需要的缩小版。
- Agent 不新增一套检索逻辑，而是从已有 `tool_finished` 事件收集引用。
- 引用在 `conversation_messages.metadata.sources` 中保存为有界快照：保留文档 ID、段落位置、命中类型、分数和最多 2048 字节片段内容。
- Agent 步骤在 `conversation_messages.metadata.agent_trace` 中保存运行 ID、状态、步骤类型、工具名和步骤状态。
- 不保存模型完整思维过程，也不把完整工具结果复制进消息表。
- 旧消息没有这些字段时保持兼容，前端不显示空卡片。

## 调用链

`knowledge_search tool_finished`
→ `agentservice.sourceCollector`
→ `agentservice.Response.Sources`
→ `handler.conversationMetadataFromAgentResponse`
→ `conversation_messages.metadata`
→ 前端 `selectConversation`
→ 引用卡片与 Agent 轨迹。

## 验证

- Go：`go test ./internal/agentservice ./internal/conversation ./internal/handler`
- 前端：`npm run build`（包含 `vue-tsc --noEmit`）
- 浏览器：本地前端可正常加载；本次冒烟未发送模型请求。后端冒烟因启动命令未加载 `.env`，数据库连接退回本机 socket，未进行真实会话恢复验证。
