# 四连切片实现记录：自动标题 / 追问换一批 / 会话更多菜单 / 正文引用标记

> 日期：2026-08-15。切片：#3 会话自动标题、#4 追问"换一批"、#7 会话更多菜单、#5 正文内引用标记（WeKnora 对照盘点）。

## #3 会话自动标题

- **方案**：不调模型，首轮问答保存后，若标题仍是默认"新对话"，用用户问题（折叠空白、取首行、截断 30 字符加 …）重命名。
- **实现**：`conversation.Service.AutoTitle`（归属校验 + 仅默认标题才改）；`handler.saveConversationExchange` 保存交换后调用，失败只 warn 不阻断；`DefaultTitle` 常量导出。
- **前端**：`refreshConversationList()` 只刷新列表不重选会话（避免消息视图被重置），问答完成后调用。
- **验证**：service 测试 ×2（截断 + 用户已命名不改）；真实链路中会话标题自动变为问题摘要。

## #4 追问"换一批"

- **方案**：follow-up-suggestions 接口本就无状态（每次调用都调模型），"换一批" = 再次调用。
- **实现**：纯前端。生成建议后按钮从"生成更具体的追问"变为"换一批"，点击重新调用同一函数替换建议。
- **验证**：前端构建通过；无后端改动。

## #7 会话更多菜单（清空消息 / 复制 Markdown）

- **清空消息**：新增 `DELETE /api/knowledge-bases/{id}/conversations/{conversationId}/messages`。事务内删除消息、摘要、幂等键三张表（每条 SQL 都带管理员归属条件），保留会话本身。`conversation.Service.ClearMessages` + `PostgresStore.ClearMessages`。
- **复制 Markdown**：纯前端，读取会话消息后拼成 `# 标题` + `**问题**/**回答**` 结构写入剪贴板。
- **UI**：会话项操作从 3 个按钮改为"⋯"菜单（置顶/改名/清空消息/复制 Markdown/删除），二次确认清空；菜单点击项后关闭，切换会话时关闭。
- **验证**：handler 测试（清空 204 且不影响其它会话消息、跨库 404）+ service/stub 更新。

## #5 正文内引用标记

- **提示词**：systemPrompt 追加引用规则——模型在引用工具资料时输出 `<kb doc_id="X" pos="Y"/>`，只允许使用工具结果中真实存在的 documentId/position。
- **渲染**：`markdown.ts` 新增 `KB_TAG_PATTERN`；`renderAnswerMarkdown` 在 marked/DOMPurify 之前把标签替换成带 data 属性的 `.kb-ref` span（避免 sanitize 丢弃未知元素）；`plainAnswerText` 让流式文本显示"〔引用〕"。
- **交互**：`.messages` 容器事件委托 `onMessagesClick` → `findSourceByRef`（按 documentId+position 匹配全局 sources）→ `openSource` 打开原文抽屉；找不到时提示。
- **兜底**：模型不输出标签时行为与之前完全一致（来源卡片照旧）。
- **验证**：真实模型问答确认模型按提示词输出 `<kb doc_id="2" pos="3"/>`；页面渲染 2 个 pill；点击打开原文抽屉（显示文件名、段落、命中类型）。渲染管道单测通过（CDP 内 import markdown.ts 断言）。
