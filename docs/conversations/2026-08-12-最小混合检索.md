# 最小混合检索

## 背景

当前系统已有 pgvector 向量检索，但精确错误码、命令、产品型号等内容不一定能被向量距离稳定召回。WeKnora 的检索配置同时包含向量阈值和关键词阈值，因此本轮增加一个可读的最小 hybrid retrieval。

## 本轮完成

- `documentchunk.PostgresStore.SearchKeyword`：在当前知识库内按 chunk 内容做大小写不敏感的包含匹配。
- `retrieval.KeywordSearcher`：定义关键词检索能力，不改变原有 `Searcher`。
- `retrieval.NewHybridService`：保留向量搜索和关键词搜索两个依赖。
- `retrieval.Service.Search`：先向量召回，再关键词召回；按轮次交错加入结果，并用 `documentID:position` 去重，最多返回请求的 limit 条。
- `cmd/server` 默认创建 hybrid retrieval，因此普通 RAG、Agent、Multi-Agent 和 MCP 复用同一条检索服务。

## 调用链

```text
问题
  → Embedding → pgvector 向量候选
  → 原文 query → PostgreSQL 关键词候选
  → retrieval.mergeResults
  → RAG distance 过滤 / Agent 工具结果限制
  → 模型
```

## 为什么暂时不用 rerank

rerank 需要额外模型调用、模型配置、成本和失败处理。先把两路召回合并跑通，更适合当前学习目标；后续可以把 rerank 放在 merge 之后作为独立阶段。

## 当前限制

关键词匹配目前是 `strpos(lower(content), lower(query))`，对长自然语言问题不够智能，也没有 PostgreSQL 全文索引；这是有意保留的最小实现，下一步可以单独升级为 token 化/`tsvector`，而不是现在混入多个复杂变化。
