# 统一 RAG 距离阈值

## 背景

WeKnora 把向量阈值作为统一的检索配置。本项目上一轮先把阈值接入标准 Agent，但普通 RAG `/chat` 仍然直接使用 Searcher 返回的所有片段，存在两条入口语义不一致的问题。

## 本轮完成

- `internal/retrieval` 新增 `DefaultMaxDistance`、`ValidateMaxDistance` 和 `FilterByMaxDistance`。
- Agent 的 `knowledge_search` 工具复用共享过滤函数。
- `rag.Service` 的旧 `Answer` / `Stream` 默认使用 `0.65`，新增 `AnswerWithThreshold` / `StreamWithThreshold`。
- 普通 `/chat` 和 `/chat/stream` 请求可传 `similarity_threshold`；不传时保持旧调用方式和默认值。
- Handler 通过可选接口调用带阈值版本，避免破坏测试替身和已有调用方。
- 过滤发生在 grounding prompt 之前，超过阈值的片段不会进入模型上下文；没有剩余资料时返回 `ErrNoSources`。

## 调用链

```text
HTTP similarity_threshold
  → Handler 解码与范围校验
  → rag.AnswerWithThreshold / StreamWithThreshold
  → retrieval.Searcher.Search
  → retrieval.FilterByMaxDistance
  → grounding prompt / SSE sources
  → 对话模型
```

## 当前限制

普通 RAG 的前端暂未单独增加阈值控件；当前页面主要使用标准 Agent 入口。协作研究和 A2A 继续沿用各自默认检索策略，避免扩大本轮范围。
