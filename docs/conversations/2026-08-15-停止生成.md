# 停止生成切片实现记录

> 日期：2026-08-15。切片：WeKnora 对照盘点 #1（首选）——用户可在标准 Agent 流式回答中主动停止生成。

## 背景

- WeKnora 输入栏在流式回答时提供停止按钮，调用 `POST /sessions/:id/stop` 立即中止。
- 我们的 Agent 多轮检索 + 长回答无法中断，只能等超时；断线重连已有但用户主动停止缺失。
- 盘点确认机制已存在：`agentruntime.Engine` 每步检查 `ctx.Err()`，`context.Canceled` 映射为 `run_canceled` 事件；`agent.AgentRun.Cancel()` 已有状态机保护；Hub 已按 runID 注册 knowledgeBaseID。只缺触发链路。

## 已确认结论

- **停止语义**：用户主动停止 = 取消执行上下文（`run_canceled`）；断线 = 不取消（继续跑，hub 重放）。两者在代码注释与本文档中明确区分。
- **停止范围**：仅标准 Agent 流式运行（有进程内 run_id 的 `agent-chat/stream`）。协作研究和 A2A 不显示停止按钮。
- **停止后的展示**：`stopped` 是独立终态，不是失败态——不显示「重新生成」；保留已输出的部分内容；无内容时显示「已停止生成。」
- **停止后的持久化**：与失败回答一致，取消的运行不写入会话历史（`saveConversationExchange` 只在成功路径执行）。当前页保留消息，刷新后该轮没有助手消息。
- **停止接口幂等**：重复 stop 返回 200 无操作；运行已结束（done）或无 cancel 注册时同样 200；未知 runID 或跨知识库返回 404。
- **错误事件不覆盖**：取消时引擎已发 `run_canceled`，handler 不再发通用 `error` 事件（原实现会发 "agent chat failed"，覆盖浏览器里的 stopped 状态）。`knowledgeBaseAgentChatError` 保持不动（它只用于非流式路径的错误映射）。

## 实现内容

后端：

- `internal/agentstream/hub.go`：`run` 结构新增 `cancel func()`；`RegisterCancel(runID, cancel)` 注册取消函数；`Cancel(runID, knowledgeBaseID)` 按知识库范围查找并只调用一次 cancel（锁外调用，避免与 hub 互斥）。
- `internal/handler/knowledge_base_agent_chat_stream.go`：执行上下文改为 `context.WithCancel(context.WithoutCancel(r.Context()))` 并注册到 hub；`errors.Is(err, context.Canceled)` 时跳过通用 error 事件。
- `internal/handler/agent_run_stop.go`（新）：`POST /api/knowledge-bases/{id}/agent-runs/{runID}/stop`，校验知识库归属后取消，返回 `{"status":"canceled"}`。
- `internal/app/server.go`：注册 stop 路由。
- 测试：hub 单测（cancel 只调一次、跨知识库拒绝、未注册无操作）；handler 集成测试（流式中 stop → `run_canceled` 且无 `run_finished`/`error`；跨知识库 404 后同库可停；405/400/404 边界）。

前端：

- `frontend/src/App.vue`：`ChatMessage.status` 增加 `"stopped"`；流式时（标准 Agent 且有 runID）composer 显示「停止生成」按钮；点击调用 stop 接口（失败自动恢复按钮）；`run_canceled` 置为 stopped、不显示重新生成、保留部分内容；`error` 事件在 stopped 状态下被忽略。
- `frontend/src/styles.css`：`.stop-button` 样式。

## 验证结果

- `go build ./...`、`go vet ./...`、`go test ./...` 全通过；前端 `npm run build` 通过。
- 真实链路（阿里云百炼 deepseek-v4-flash + 知识库 1）：流式请求发出后立即 `POST stop` → 返回 200 `{"status":"canceled"}`，SSE 只含 `run_started` + `run_canceled`，无 `run_finished`、无 `error`。服务端日志确认模型 HTTP 调用响应 context canceled，228ms 内停止。
- 真实浏览器（headless Edge + CDP）：输入问题发送 → 流式中「停止生成」按钮出现 → 点击 → 流结束、按钮消失 → 消息显示「已停止生成。」、Agent 轨迹为 ["Agent 开始运行", "Agent 已停止"]、不显示「重新生成」。截图 `/tmp/n2sql-stop-smoke.png`。

## 待办与未决

- 停止后不写会话历史：若用户反馈需要「停止的回答也应可见」，可后续把 stopped 快照写入消息（新增终态字段），当前不做。
- 协作研究模式的多智能体流是否也要停止入口：当前研究模式无 hub 注册，需要先给 multi-agent stream 加 run 管理，已列入候选。
- 断线后恢复中的回答同样可停止（hub 同一 run），已隐式支持，未单独测试。
