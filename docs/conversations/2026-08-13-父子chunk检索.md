# 父子 chunk 检索

## 背景

邻近 chunk 扩展可以补充命中片段前后各一块，但仍可能被切分边界打断。本轮参考 WeKnora 的 parent-child 思路：小子块负责检索，大父块负责提供回答上下文。

## 已完成

- 新迁移 `000016_add_parent_chunks.up.sql` 增加 `document_parent_chunks` 表。
- `document_chunks.parent_chunk_id` 建立子块到父块的外键，父块删除时子块级联删除。
- 文档 Worker 使用约 3000 字符父块和约 1000 字符子块；只有子块调用 Embedding。
- PostgreSQL `ReplaceHierarchical` 在同一事务中替换父块、子块和子块向量。
- 检索命中子块后，先通过 `ParentForChunk` 查询父块；命中旧数据且没有父块时，继续使用前后邻近 chunk 扩展。
- RAG 和 Agent 的模型上下文使用父块加命中子块；引用仍保留子块的 `documentId`、`position` 和分数。
- 前端引用详情显示父块上下文，并继续标注命中的子块位置。

## 调用链

上传文档 → Worker 提取全文 → 父块切分 → 子块切分 → 仅子块 Embedding → 保存父子关系 → 子块向量/关键词检索 → 查询父块 → RAG/Agent prompt。

## 兼容和边界

- 旧 chunk 的 `parent_chunk_id` 为 NULL，因此不会报错，会退回原有邻近扩展。
- 父块不参与向量检索，避免大块文本降低召回精度和增加 embedding 成本。
- 子块的位置仍是原有引用位置，前端可以准确定位命中段落。
- 当前父块查询按最终结果逐条读取；数据量更大时可以改为批量查询。
- 本轮已改为批量查询：一次收集所有命中子块引用，通过一条 SQL 加载父块，再映射回每个结果；没有父块的旧 chunk 继续邻近扩展。
