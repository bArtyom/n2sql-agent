# 工具结果类型化渲染切片实现记录

> 日期：2026-08-15。切片：WeKnora 对照盘点 #12——工具结果按类型渲染（文档列表表格、文档信息键值对），取代纯文本摘要。

## 背景

- WeKnora 有 15 个类型化渲染组件：搜索结果按文档分组+命中词高亮、文档信息、数据库结果表格、Web 搜索、grep 高亮等。
- 我们之前工具轨迹展开后只有参数（JSON 文本）和结果摘要（`result_summary` 纯文本，如"返回 N 条资料"）。
- 本项目 4 个只读工具：`knowledge_search`（已有 sources 卡片）、`document_list`、`document_info`、`document_read`。

## 已确认结论

- **类型化范围**：本次只做 `document_list`（表格）和 `document_info`（键值对）。`knowledge_search`/`document_read` 的 sources 已有引用卡片点击打开原文，不重复。
- **数据边界**：结构化 metadata 完全复用工具已有的有界输出（document_list 的 `selected` 列表本身受 maxResults 和 maxBytes 限制；document_info 单条），不新增不受限数据。
- **实时 vs 历史**：结构化数据随 `tool_finished` SSE 事件实时传输；历史恢复（traceCollector 有界摘要）仍显示文本摘要，不扩展持久化格式。
- **工具完成 label**：顺手修正了既有小缺陷——之前任何工具完成都显示"知识库检索完成"，现在按工具显示"知识库检索完成/查看文档列表完成/查看文档状态完成/读取文档正文完成"。

## 实现内容

后端：

- `document_list_tool.go`：`marshalDocumentList` 返回 `(content, selected, err)`，`Call` 把 `selected` 放入 `Metadata["documents"]`。
- `document_info_tool.go`：找到文档后构造 `documentListItem` 放入 `Metadata["document_info"]`。
- `agentruntime/engine.go`：`tool_finished` 事件透传 `documents` / `document_info`（与 sources/truncated 同样的白名单方式）。

前端：

- `App.vue`：新增 `AgentDocument` 类型；`AgentEvent` 加 `documents`/`documentInfo`；`finishLastAgentToolEvent` 改对象参数并写入结构化字段；`toolFinishedLabel` 按工具名生成完成 label；`parseAgentDocuments`/`parseAgentDocumentInfo` 解析（有界，最多 20 条）。
- 模板：展开的工具轨迹中，`trace.documents` 渲染表格（文档/类型/大小/状态，复用 `formatBytes`/`statusLabel`），`trace.documentInfo` 渲染键值卡片。
- `styles.css`：`.agent-trace-table`（紧凑表格）、`.agent-trace-info`（键值卡片）。

## 验证结果

- `go build/vet/test` + 前端构建通过；rag/agent/agentruntime 相关测试无回归。
- 真实链路（headless Edge + CDP）：问"这个知识库里目前有哪些文档？"→ 模型调用 `document_list` → 轨迹行显示"查看文档列表完成" → 展开渲染出 2 行表格（文档/类型/大小/状态）。截图 `/tmp/n2sql-typed-smoke.png`。
