# 第二阶段第一小步：HTTP 与 Worker 优雅退出

## 背景

用户决定跳过真实扫描 PDF OCR 验收，进入第二阶段“后端工程化与可靠性”。按照计划，先处理 Worker 和 HTTP 服务的生命周期，再接入 Redis 队列、重试和死信。

## 已完成

- `app.RunServer` 统一处理 HTTP 监听、信号取消和优雅关闭；收到 `SIGINT/SIGTERM` 后停止接收新请求，并等待活动请求结束。
- `cmd/server/main.go` 使用 `signal.NotifyContext` 同时驱动 HTTP 服务和 Worker；服务退出前等待 Worker goroutine 结束。
- `worker.Run` 在上下文已取消时不再领取新任务。
- Worker 处理中的任务收到 `context.Canceled` 时保持 `processing`，不误标记为 `failed`，为后续 stale claim 恢复留下入口。
- Worker 增加 `started/canceled/succeeded` 任务日志，并保留已有失败日志。

## 验证

- `go test ./...` 通过。
- `go vet ./...` 通过。
- 新增 Runner 取消行为和 HTTP 生命周期单元测试。
