# Go 接口分层学习记录

## 背景

在完成模型服务配置的读取与保存接口后，围绕 Go 项目的代码组织、变量传递和接口设计进行了逐步讲解。本文用于保留后续开发时可复用的理解框架。

## 已确认结论

### 学习式提问约定

- 用户提出技术问题后，先给出一版不改变原意、但更清晰且上下文完整的问题重写，再回答原问题。
- 对逐题测验或 grilling 类对话，问题重写保持简短，避免打断学习节奏。

### 一个 HTTP 接口的职责分层

同一个业务功能不是重复写在多个位置，而是按职责拆分：

```text
HTTP 请求
  -> Handler：URL 对应的 HTTP 处理、JSON 解析、输入校验、状态码和响应
  -> Store：业务数据的读取与保存能力约定
  -> PostgresStore：实际执行 SQL
  -> PostgreSQL
```

- `handler` 只关心 HTTP：请求方法、请求体、校验、`400/404/500`、JSON 响应。
- 业务包（如 `modelprovider`）只关心该业务的数据结构和数据读写。
- `PostgresStore` 负责 SQL，不应处理 URL、JSON 或 HTTP 状态码。
- 调用外部模型服务等联网能力，应放到独立 Client；不要塞进 `PostgresStore`。

### 当前模型配置接口的代码链路

```text
main 创建 db
  -> modelprovider.NewPostgresStore(db)
  -> app.New(...)
  -> 注册 GET /api/model-provider 和 PUT /api/model-provider
  -> handler.NewModelProvider(...)
  -> store.Current / store.Save
  -> PostgresStore 使用 store.db 执行 SQL
```

- `modelprovider`、`app`、`handler`、`sql` 是包名，不是变量。
- `cfg`、`db`、`providerStore`、`providers`、`store` 是变量或函数参数。
- `providerStore`（`main`）、`providers`（`app.New`）和 `store`（Handler）是同一个对象在不同函数作用域中的不同名字；它内部持有同一个 `db`。
- `NewXxx` 是 Go 的常见约定：创建并返回一个可使用对象。执行动作的函数通常使用 `Save`、`Current`、`Apply` 等动词。

### GET 与 PUT 的区别

- `GET /api/model-provider`：从数据库读取已有配置，再返回 JSON，核心是 `store.Current(...)`。
- `PUT /api/model-provider`：读取前端 JSON、校验输入、写入数据库、返回保存结果，核心是 `Decode -> 校验 -> store.Save(...) -> JSON`。

### Context 的作用

- `ctx` 来自 `r.Context()`，它表示本次 HTTP 请求的生命周期状态。
- 它会沿着 `Handler -> Store -> QueryRowContext` 向下传递取消、超时和请求级信息。
- 若浏览器取消请求或客户端断开，使用该 `ctx` 的数据库操作可以停止无意义的等待。
- `ctx` 不包含 JSON 请求体、数据库连接、模型配置或 API Key；它不是让代码执行的开关。

### 未来新增业务模块的方式

例如未来新增用户功能时，按照以下顺序实施：

1. 新建数据库迁移，创建或调整相关表。
2. 建立 `internal/user` 业务包，定义 `User` 数据结构。
3. 定义 `user.Store` 所需的数据读写能力，并由 `user.PostgresStore` 实现 SQL。
4. 新建用户 Handler，负责用户相关 URL 的 JSON、校验和 HTTP 响应。
5. 在 `app.New` 中注册用户 URL 到用户 Handler。
6. 在 `main` 中复用同一个 `db`，创建 `user.NewPostgresStore(db)` 并注入 `app.New`。
7. 按测试优先的方式验证 Handler 行为和真实数据库行为。

整个后端只在启动时创建一次 `db`，不同业务模块共享它：

```text
db
├─ modelprovider.PostgresStore
├─ user.PostgresStore
└─ 后续知识库相关 PostgresStore
```
