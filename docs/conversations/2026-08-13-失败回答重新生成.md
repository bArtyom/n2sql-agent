# 失败回答重新生成

## 背景

标准 Agent 使用 SSE 输出。模型、网络或服务端异常时，页面已经创建了一个助手消息，但这次运行可能没有得到完整回答。下一步先补一个用户可见的恢复入口，不改变后端协议和数据库结构。

## 本轮实现

- 助手消息保存原始问题、会话 ID 和运行模式，历史加载的旧消息不伪造这些字段。
- 标准 Agent 在 `run_failed`、`run_canceled` 或流提前结束时显示“重新生成”。
- 点击后清空本次未完成回答的内容、引用和运行轨迹，复用现有 `agent-chat/stream` 接口重新请求。
- 重试继续使用当前知识库、会话、召回数量、相似度阈值、文档范围和改写开关。
- 研究模式不显示此按钮；回答已经生成但 `conversation_save_failed` 时也不重试，避免重复保存同一个回答。

## 调用链

`重新生成` 按钮 → `retryAnswer` → `streamAgentQuestion` → 既有 SSE Handler → Agent Service/Engine → 检索与模型 → 既有会话保存和 SSE 事件解析。

这次没有新增 Go Handler、数据库表或模型调用协议，只把原来写在 `askQuestion` 中的流式请求提取成可复用函数。

## 后续边界

本轮只处理失败或中断回答。对已经成功的消息进行编辑、分支会话、重新生成后替换历史回答，需要先确定消息版本和会话分叉规则，暂不混入本切片。

## 验证

- `cd frontend && npm run build`：通过。
- 需要在浏览器中确认按钮显示、点击后状态回到流式运行；若本地没有可用数据库或模型 API Key，只能完成页面加载冒烟，不能验证真实模型重试。
