# 知识库数据模型

## 背景

第一阶段进入“知识库与文件管理”。本小步只建立三张表的版本化迁移，不实现文件上传、Worker、文档切分、向量或问答。

## 表关系

```text
administrators
  └─ knowledge_bases
       └─ documents
            └─ document_processing_tasks
```

- `knowledge_bases`：一个管理员拥有多个知识库；同一管理员下的名称不能重复。
- `documents`：记录原始文件名、存储相对路径、MIME 类型与大小。存储路径不能为空、绝对路径或包含 `..`，以防止之后的文件操作发生路径穿越。处理状态只存在任务表，避免两处状态不一致。
- `document_processing_tasks`：记录后台处理的重试次数、开始/完成时间以及错误信息。
- 删除知识库会级联删除其文档与任务记录；文件本身的清理将在后续删除知识库的应用层流程中单独处理。

## 已确认状态

- 状态统一为 `pending`、`processing`、`succeeded`、`failed`，且由数据库 `CHECK` 约束。
- 同一文档同时只能有一条 `pending` 或 `processing` 任务，避免多个 Worker 重复处理。`pending` 队列也有局部索引，后续 Worker 只需快速查找待处理任务。
- 数据库只接受 `text/markdown`、`text/plain` 与 `application/pdf` 三种首版支持类型。
- 三张表都继续使用已有 `refresh_updated_at()` 触发器维护 `updated_at`。
