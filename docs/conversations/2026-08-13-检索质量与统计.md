# 检索质量与统计

## 背景

本轮按 WeKnora 的检索主线补齐混合召回的质量和可观测性；HNSW、父块/邻近块/上下文扩展继续后置。

## 已完成

- Rerank 调用失败时保留统一融合后的候选结果；只有请求取消或超时才继续返回错误。
- 关键词检索增加 `keyword_threshold`，默认值为 `0.10`。PostgreSQL 精确短语命中会把分数归一到 `1.0`，避免被误过滤。
- 向量和关键词结果用 RRF（Reciprocal Rank Fusion）统一排序。重复 chunk 的两路排名分数会相加，结果增加 `fusionScore`。
- retrieval observation 记录向量候选数、关键词候选数、阈值后数量、拒绝数量、去重后数量、Rerank 前后数量、最终过滤数量和是否降级。
- 统计通过 context observer 传递到普通搜索响应、RAG 响应、Agent `RunStats`、Multi-Agent 响应和前端检索统计条。
- 前端增加关键词下限控件，并展示“向量、关键词→阈值后、去重、重排、最终、Rerank 降级”。API Key 仍只在后端环境变量中。

## 调用链

```text
HTTP/Agent/RAG
  → retrieval.SearchOptions(keyword_threshold)
  → pgvector + PostgreSQL FTS
  → 关键词阈值
  → RRF 融合与去重
  → Rerank（失败则回退融合结果）
  → 距离最终过滤
  → retrieval observation / sources
```

## 验证与限制

- `go test ./...` 通过，`frontend` 的 `npm run build` 通过；浏览器已确认页面能加载，因后端接口未启动出现预期的 500 提示，因此没有做真实模型召回验证。
- 目前没有创建 HNSW 迁移：embedding 列维度仍需固定后再做，避免换模型或空表时索引不匹配。
- 父块、邻近块和上下文扩展不在本轮实现，后续单独设计结果数量和 prompt 字节预算。
