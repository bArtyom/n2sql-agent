# 多入口文档范围筛选

## 背景

标准 Agent 已支持通过 `document_ids` 限定检索文档。本轮把同一语义补到协作研究和异步 A2A，避免不同入口出现不同的检索范围行为。

## 已完成

- 协作研究的普通接口和 SSE 接口都传递 `retrieval.SearchOptions`。
- Researcher 创建的只读 `knowledge_search` 工具复用知识库范围和文档 ID 范围。
- A2A 任务请求接收并校验 `document_ids`，PostgreSQL 任务表以 `BIGINT[]` 持久化，后台 Runner 执行时再次传给 Supervisor。
- 前端在标准 Agent、协作研究、异步任务三种模式中都可以勾选已处理完成的文档；不勾选时仍检索整个知识库。

## 数据流

`App.vue` 勾选文档 → 请求 `document_ids` → Handler 统一校验/排序/去重 → Supervisor 或 A2A TaskStore → retrieval `SearchOptions` → PostgreSQL vector/keyword 查询的 `document_id = ANY(...)`。

## 当前限制

- A2A 数据库迁移 `000014_add_a2a_document_filter.up.sql` 需要在实际部署环境运行 `go run ./cmd/migrate`。
- 本轮没有调用真实模型，也没有进行真实数据库迁移验证；Go 单元测试、静态检查和前端构建已通过。

## 下一步

Query Rewrite / Multi-Query 已接入：用户可以打开“多查询改写”，模型最多生成 2 个变体，原问题始终保留，所有变体复用 hybrid retrieval、去重和 rerank；不新增知识库业务表。注意每个变体都会额外消耗 embedding，改写本身还会消耗一次 chat token，并增加延迟。
