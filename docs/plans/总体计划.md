# 项目与学习总计划

## 总目标

围绕两类目标岗位准备：

- 后端工程：Go、数据结构与算法、MySQL/Redis/消息队列、并发、分布式、可靠性和性能优化。
- Agent 平台：Agent Runtime、工具调用、ReAct/PlanAct/CodeAct、MCP、A2A、Multi-Agent、异步任务与资源调度。

最终要形成一套能够面试讲清楚、能够独立实现、能够压测和排障的项目，而不是只会启动一个现成项目。

## 项目分工

- `n2sql-agent`：唯一的独立实现、实验和面试展示项目。所有新增功能、测试和配置只在此目录完成。
- `WeKnora`：生产级架构教材。重点阅读其 Agent、任务队列、Worker、限流、MCP、观测和权限实现，理解设计取舍，不直接复制源码。
- 算法与计算机基础：独立学习和刷题，不能假设做完项目就自然掌握。

## 长期编码与学习标准

- 所有新增 Go 代码优先使用惯用、直白、适合初学者阅读的写法：命名清楚、控制流顺序自然、函数保持单一职责，并避免为了少几个文件而混合 HTTP、业务、存储和调度逻辑。
- 具有不同频率或生命周期的后台工作要分开调度。例如任务轮询和终态清理分别使用清晰的 ticker、循环或 worker；不能依赖一个任务执行完后顺便判断另一个任务是否到期来隐藏调度关系。
- 每个小功能交付时，除了测试和代码说明，还要用一个最小 Go 示例解释关键语法、入口、调用链、退出条件和并发边界。

## 已完成阶段：知识库问答底座

当前项目已经完成文档上传、异步处理、切分、向量化、pgvector 检索、非流式 RAG、SSE 流式问答、引用来源和最小 OCR 骨架，已具备可运行的知识库问答闭环。

阶段结论：第一阶段目标已经达到。OCR 只做一次真实扫描 PDF 验证即可，不继续扩展成完整文档解析平台；后续主线先切换到 Agent 能力，再补后端工程化。

## 第二阶段：Agent Runtime 核心与必要工程化

目标：在现有 RAG 上优先实现一个可解释、可限制、可测试的 Agent 最小闭环。工程化只补齐 Agent 当前需要的取消、超时、错误和事件边界，不先引入 Redis 等额外基础设施。

- 建立 `Agent`、`Tool`、`ToolRegistry`、`Run`、`Step`、`Event` 等清晰接口。
- 实现模型 Function Calling 和最小 ReAct 循环：思考/工具调用/工具结果/最终回答。
- 将知识库检索和文档查询封装成只读工具；其他数据类工具后置，当前不引入 schema 或 SQL 主题。
- 增加步骤数、总耗时、Token、工具超时、取消和错误预算，避免 Agent 无限循环。
- 实现上下文拼接、短期会话记忆、历史压缩和引用来源保留。
- 通过 SSE 输出 Agent 事件，使前端能够展示每一步，而不只展示最终文本。

阶段验收：能够演示“问题 → 知识库检索工具 → 工具结果 → 最终回答”的完整 Agent Run；不依赖框架黑盒讲清状态变化；能够测试工具失败、超时、取消和循环上限。

## 第三阶段：后端工程化与可靠性

目标：在 Agent 主链路稳定后，把服务提升为能说明并发、失败恢复和性能的后端服务。

- 将现有数据库轮询任务抽象成队列接口，保留 PostgreSQL 实现作为基线。
- 引入 Redis-backed task queue，明确缓存、限流、幂等键和短期状态的边界。
- 实现重试、退避、超时、死信、并发上限和 stale claim 恢复。
- 补齐请求 ID、结构化日志、基础指标、pprof 和可重复的压测脚本。
- 保留 PostgreSQL 任务表作为可靠性兜底或对照实现，解释数据库队列与 Redis/MQ 的取舍。

阶段验收：能够画出 Agent 请求、任务队列、Worker、数据库和模型服务的时序图；能够复现一次失败重试和并发控制；能够用数据说明一次性能优化。

## 第四阶段：MCP、Multi-Agent 与 A2A

目标：覆盖 Agent 平台岗位中最有辨识度的协议和编排能力，但控制实现规模。

- 先实现进程内 Supervisor/Researcher/Answerer 三角色协作，使用任务状态和结构化消息通信。
- 将工具注册和调用适配为 MCP Client/Server；优先实现知识库搜索、文档列表等只读工具。
- 再实现一个最小 A2A HTTP 适配层：Agent Card、任务创建、状态查询、结果返回和错误状态。
- 用统一事件模型兼容单 Agent、Multi-Agent、MCP 和 A2A，避免每种协议各写一套业务逻辑。
- 研究 PlanAct/CodeAct 的边界；CodeAct 只做设计和安全分析，除非后续有明确场景，不默认接入任意代码执行。

阶段验收：能够解释 Function Calling、MCP、A2A 的边界；能够演示两个 Agent 的协作链路；能够说明沙箱、权限、超时和工具注入风险。

## 第五阶段：评测、观测与面试交付

- 建立 30—50 条固定问答集，记录检索召回、引用准确性、工具成功率、最终回答质量和模型成本。
- 为 Agent Run 增加 trace/span 或等价的结构化执行记录，支持按 run 排查失败步骤。
- 补充架构图、关键设计决策、压测结果、故障复盘和 Trade-off 文档。
- 准备 3 个项目故事：队列可靠性、Agent 工具调用、性能/稳定性优化；每个故事都按背景—问题—方案—指标—取舍讲述。

## 明确不做的事情

- 不把所有时间投入到 OCR、复杂版面、网页抓取、IM 接入或多种向量数据库适配。
- 不同时深入 Eino、LangChain、AutoGPT、CrewAI 等多个框架；以 WeKnora 的实现和一个主力 Go Agent 实现为主，其他框架只做概念对照。
- 不把“读过 WeKnora 源码”当作“掌握了能力”；每个重点模块至少要在 n2sql 中实现一个缩小版并写测试。
- 不在没有指标和验收条件时进行大范围重构。

## 默认学习时间分配

按每周 10—15 小时计算：项目开发 50%，后端/计算机基础 30%，算法与面试表达 20%。如果时间更少，按阶段顺延，不同时压缩所有内容。

具体周计划见 `学习与面试计划.md`，具体开发切片见 `第二阶段-Agent平台与后端工程化.md`。
