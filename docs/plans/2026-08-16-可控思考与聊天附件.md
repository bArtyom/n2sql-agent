# Spec: 可控思考模式与聊天附件/图片

## Objective

在标准 Agent 问答中增加两个用户可见能力：

1. 用户选择 `fast`、`standard`、`deep` 三档思考级别，后端将其映射为 OpenAI-compatible `reasoning_effort` 参数。
2. 用户可以在当前问题中附加图片或文本文件；附件只参与本轮模型请求，不写入会话历史和知识库。

本轮不实现供应商专属参数发现，不把附件做成知识库文档，也不保存完整思考内容。

## Assumptions

- 当前聊天入口使用 OpenAI-compatible `/chat/completions`。
- `reasoning_effort` 由 Provider/模型决定是否支持；不支持时由上游返回错误，后端不伪造效果。
- 只支持 PNG/JPEG/WEBP 图片，以及 TXT/Markdown 文本附件。
- 单轮最多 3 个附件；单个图片最大 4 MiB，单个文本最大 128 KiB；总请求仍受后端上限约束。
- 附件使用 JSON base64 传输，服务端解码后转换为 OpenAI 多模态 `content` parts；不落盘。
- 附件只用于标准 Agent，Research/A2A 保持现有请求契约。

## API Contract

`agent-chat` 和 `agent-chat/stream` 请求增加：

```json
{
  "message": "请分析这张图",
  "thinking_mode": "deep",
  "attachments": [
    {
      "filename": "chart.png",
      "content_type": "image/png",
      "data_base64": "..."
    }
  ]
}
```

思考级别：空值/`standard` 不额外限制；`fast` 映射 `reasoning_effort=low`；`standard` 映射 `medium`；`deep` 映射 `high`。

附件内部转换为：

```json
{
  "role": "user",
  "content": [
    {"type": "text", "text": "请分析这张图"},
    {"type": "image_url", "image_url": {"url": "data:image/png;base64,..."}}
  ]
}
```

文本附件转换为 text part，并带文件名边界说明；文件名和内容都视为不可信数据。

## Backend Design

- `modelclient.ChatRequest` 增加可选 `ReasoningEffort`。
- `modelclient.ChatMessage` 增加只用于出站 JSON 的 `Parts`，无附件时继续发送字符串 `content`，保持兼容。
- `agentservice.ChatRequest` 增加 `ThinkingMode` 与附件输入；入口校验枚举、数量、base64、媒体类型和大小。
- Agent 最后一条 user message 由文本和附件 parts 组成；历史与数据库仍只保留纯文本问题和答案。
- SSE 的 `reasoning_delta` 继续展示模型实际返回的思考内容。
- 幂等请求哈希包含思考级别和附件内容摘要，避免同一 key 错误复用不同附件请求。

## Frontend Behavior

- 标准 Agent 输入区增加思考级别选择器和附件按钮。
- 支持选择、预览、删除图片/文本附件；发送前读取为 base64。
- 图片显示缩略图，文本显示文件名和大小。
- 发送后清空当前附件；失败时保留消息重试所需的原始附件状态不在本轮实现，重试只重发文本。
- Research/A2A 模式隐藏附件与思考级别选择器，避免发送不兼容字段。

## Security and Limits

- 服务端不信任前端 `content_type`，同时检查允许类型、文件名、base64 解码结果和字节上限。
- 不允许 SVG、HTML、脚本、PDF、可执行文件或任意 URL。
- 图片只生成 `data:` URL 作为模型请求内容，不在前端使用 `innerHTML`。
- 不记录 base64、图片正文或完整附件内容到日志。

## Testing Strategy

- modelclient：思考参数和多模态 content JSON 序列化。
- agentservice/handler：思考级别、附件类型、数量、base64、大小和 idempotency hash。
- engine：带附件的 user message 保留 parts，并且普通文本请求 JSON 不变。
- 前端：`vue-tsc --noEmit && vite build`；使用真实浏览器验证选择、预览、删除和发送前状态。

## Success Criteria

- `fast/standard/deep` 能被后端验证并映射到请求参数。
- 支持的图片/文本附件能进入一次 Agent 模型请求。
- 非法类型、超限、错误 base64 被拒绝且不落盘。
- 原有无附件 Agent、工具调用、会话历史和 SSE 行为不回归。
- Go tests、go vet、前端 build 和浏览器冒烟通过。

## Boundaries

- Always：服务端校验、大小上限、脱敏思考、测试和增量提交。
- Ask first：新增 Provider 专属参数、附件持久化、知识库自动入库、视频/音频附件。
- Never：把附件内容拼入 SQL、写入日志、渲染为未经转义 HTML，或将用户选择的思考级别当作安全权限。
