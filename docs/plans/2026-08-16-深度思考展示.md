# Spec：标准 Agent 深度思考展示

## Objective

让支持 OpenAI 兼容 `reasoning_content` 的聊天模型，在标准 Agent 的 SSE 回答中显示一个默认折叠的“深度思考”卡片。用户可以展开查看本轮模型返回的思考内容；没有该字段的模型行为保持不变。

本轮只做展示链路，不改变 Agent 的提示词、工具调用、模型选择、会话数据表或回答正文。思考内容只保留在当前页面和进程内 SSE 重放中，不写入会话历史，避免把模型内部推理长期存入数据库。

## Assumptions

1. 当前聊天服务使用 OpenAI-compatible `/chat/completions`，模型可能在 `choices[0].message.reasoning_content` 返回思考内容。
2. 标准 Agent 的模型调用是非流式的，因此思考内容在一次模型调用完成后随 Agent 事件送达；本轮不改 RAG 流式接口。
3. “深度思考”是供应商返回的非可信文本，服务端做长度上限和已有安全脱敏，前端按普通文本显示，不执行其中的指令或 HTML。
4. 没有 reasoning 字段的模型不显示空卡片，旧 API 请求和响应保持兼容。

## Interface Contract

- `modelclient.ChatResponse` 增加可选 `ReasoningContent`，读取 `reasoning_content`。
- `agent.Event` 增加 `reasoning_delta` 类型；数据为 `{content: string}`，单次和累计内容都受上限约束。
- Agent SSE 允许新增 `reasoning_delta` 事件，旧客户端忽略该事件仍可正常显示答案。
- 前端 `ChatMessage` 增加当前页字段 `reasoningContent` 和 `reasoningExpanded`，不进入会话 metadata。

## UI Behaviour

- 标准 Agent 回答出现思考内容时，在回答正文前显示“深度思考”折叠卡片。
- 默认折叠；按钮有 `aria-expanded` 和明确的中文无障碍名称。
- 生成中显示“正在思考…”；生成完成显示“已完成”，失败或停止时保留已收到的内容。
- 没有思考内容时不改变现有轨迹布局。
- 只在标准 Agent 模式显示，不影响协作研究和 A2A。

## Commands

- Go tests: `go test ./internal/modelclient ./internal/agentruntime ./internal/agentservice ./internal/handler`
- Go vet: `go vet ./internal/modelclient ./internal/agentruntime ./internal/agentservice ./internal/handler`
- Frontend: `cd frontend && npm run build`

## Project Structure

- `internal/modelclient/`：解析外部模型响应。
- `internal/agent/`、`internal/agentruntime/`：定义和发出 Agent 事件。
- `internal/handler/`：将事件写成 SSE。
- `frontend/src/App.vue`、`frontend/src/styles.css`：当前回答状态和折叠卡片。
- `internal/*/*_test.go`：边界和事件链路测试。

## Code Style

Go 事件数据使用小而明确的 `map[string]any`，边界文本先脱敏再截断；Vue 延续当前 `ref` 状态和原生 `<button>` 交互：

```go
if reasoning := boundedReasoning(response.ReasoningContent); reasoning != "" {
	if err := emitter.emit(agent.EventReasoningDelta, step, map[string]any{"content": reasoning}); err != nil {
		return finishError(result, err)
	}
}
```

## Testing Strategy

- `modelclient`：解析有/无 `reasoning_content`，验证长度上限和既有正文/工具调用不受影响。
- `agentruntime`：有思考内容时事件顺序包含 `reasoning_delta`，无思考内容时不增加空事件。
- `handler`：SSE 接受并转发新事件，旧事件顺序不变。
- 前端：用 TypeScript/Vite 构建验证类型和模板；真实浏览器验证若环境提供 DevTools 通道，再检查折叠、键盘和响应式布局。

## Boundaries

- Always：限制思考内容大小、使用已有脱敏、默认折叠、保持旧客户端兼容、补充测试。
- Ask first：引入新的模型 SDK、数据库字段、持久化 reasoning、流式改造或改变系统提示词。
- Never：把 API Key、请求头、模型 URL、原始内部异常或未限制的 reasoning 写入 SSE/数据库。

## Success Criteria

- 支持 `reasoning_content` 的响应会产生一个有界的 `reasoning_delta` SSE 事件。
- 前端能在当前回答中默认折叠并用键盘展开/收起思考内容。
- 无 reasoning 字段的旧模型和旧客户端继续正常工作。
- 相关 Go 测试、静态检查和前端构建通过。
