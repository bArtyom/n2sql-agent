# 学习与面试计划

## 使用方式

按每周 10—15 小时设计：项目开发约 50%，后端与计算机基础约 30%，算法和面试表达约 20%。时间不足时顺延周数，不要把所有主题都压缩成只看概念。

每周固定产出：

- 一个可运行的项目切片。
- 一页设计/故障复盘笔记。
- 5—8 道高质量算法题，重点复盘而不是追求数量。
- 一次 10 分钟口述，说明本周代码的取舍和失败路径。

## 后续双主线学习方式

- Agent 学习顺序：先看 DeerFlow 的 Run、Worker、事件流和 checkpoint，再看 WeKnora 的工具、会话、审批和用户可见轨迹，最后在 n2sql 中实现缩小版。
- RAG 学习顺序：以 WeKnora 的文档处理、混合检索、引用和会话知识库为主；每次改动都记录召回、过滤、引用和回答之间的关系。
- 每个切片必须产出一个最小 Go 示例，说明入口、状态变化、事件流、错误路径和退出条件。
- 不把 Redis、checkpoint、子 Agent 等概念直接等同于功能完成；必须在 n2sql 中有代码、测试和可运行验证才算完成。

## 八周主计划

### 第 1 周：Agent 建模与 Go 执行边界

- 学习：LLM 消息结构、goroutine、context、取消、超时和优雅退出。
- 项目：定义 `Agent`、`Tool`、`ToolRegistry`、`AgentRun`、`Step` 和 `Event`。
- 阅读：WeKnora 的 Agent Engine、tool registry 和 chat model 类型。
- 面试：能够画出一次 Agent Run 的状态变化和取消路径。

### 第 2 周：知识库工具与 Function Calling

- 学习：Function Calling、JSON Schema、参数校验和模型失败类型。
- 项目：将知识库检索封装为只读工具，完成工具注册、调用和结果回传。
- 面试：能够解释模型为什么不能直接执行工具，以及服务端如何校验工具参数。

### 第 3 周：ReAct、事件流与上下文

- 学习：ReAct、步骤状态、Token 上下文、短期记忆和历史压缩。
- 项目：实现最大步数、总耗时、连续失败限制，并通过 SSE 输出 Agent 事件。
- 面试：能够画出“用户请求—模型决策—工具—结果—回答”的时序图。

### 第 4 周：Agent 安全与评测

- 学习：Prompt Injection、越权工具、敏感数据回显、工具超时和错误预算。
- 项目：补齐工具结果长度限制、取消、失败测试和知识库引用保留。
- 产出：一组最小 Agent 评测集和一次失败路径复盘。

### 第 5 周：Redis、任务队列与消息语义

- 学习：Redis 数据结构、至少一次、至多一次、幂等、重试和死信。
- 项目：抽象 `TaskQueue`，补并发上限、重试、退避、超时和失败状态。
- 阅读：WeKnora 的 task queue、Asynq worker pool 和模型并发治理。

### 第 6 周：性能、可靠性与排障

- 学习：HTTP 超时、连接池、缓存策略、pprof、metrics、P95/P99、容量估算。
- 项目：接入 Redis-backed queue，补压测、指标和一次真实性能优化。
- 产出：一页基线—改动—结果的性能报告。

### 第 7 周：MCP、Multi-Agent 与 A2A

- 学习：Supervisor、角色分工、结构化消息、MCP Client/Server 和 A2A Agent Card。
- 项目：实现 Researcher/Answerer 两角色协作，再补最小 MCP 和 A2A HTTP 适配。
- 面试：对比 Function Calling、MCP、A2A 和 Multi-Agent 的边界。

### 第 8 周：总结与面试交付

- 学习：RAG/Agent 评测、召回率、引用准确性、工具成功率、成本和可观测性。
- 项目：整理 30—50 条评测集、架构图、压测报告、故障复盘和 README。
- 面试：完成 Go/后端基础、系统设计和项目深挖三次模拟。

## 长期并行基础线

项目推进期间每天或隔天保持两条短线：

- 算法：数组/链表/树/图、二分、滑窗、DFS/BFS、堆、并查集、动态规划；每题写出复杂度和边界条件。
- 后端基础：Go runtime 与并发、MySQL/InnoDB、Redis、消息队列、TCP/HTTP、Linux、分布式一致性和系统设计。

其中 MySQL 需要单独补齐：n2sql 当前核心存储是 PostgreSQL，WeKnora 中的 MySQL 驱动也主要服务 Doris 连接，不能把它们当作已经掌握 MySQL。至少要完成索引/事务/锁/隔离级别/执行计划/分库分表的专项笔记和题目。

## 学习资料优先级

1. 当前项目代码与测试：先理解并修改自己的实现。
2. WeKnora 对应模块：按问题阅读 Agent、队列、Worker、MCP、限流和观测。
3. Agent 资料：Datawhale `hello-agents`、Eino、MCP Go SDK、A2A SDK，重点看最小实现和协议原理。
4. 后端面经：CS-Notes、go-questions、7days-golang、system-design-primer，以及高质量 Go 面试题仓库。

不要把收藏仓库数量当作学习进度；每看一个主题都要回到代码里做一个缩小版、测试一个失败路径、写一段自己的解释。

## 求职前自测门槛

- 能独立画出 n2sql 的整体架构和 Agent Run 时序。
- 能解释 PostgreSQL 队列、Redis 任务队列和 Kafka/RocketMQ 的适用边界。
- 能手写或讲清常见并发、缓存、幂等、重试、限流和优雅退出方案。
- 能从零写出一个带参数校验、超时、权限和错误处理的 Tool。
- 能区分并解释 ReAct、PlanAct、CodeAct、MCP、A2A 和 Multi-Agent。
- 能诚实说明项目已经实现、部分实现和未实现的内容。
