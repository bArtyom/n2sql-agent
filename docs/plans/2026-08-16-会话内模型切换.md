# 会话内模型切换规格

## 目标

让标准 Agent 会话可以从服务端配置的聊天模型列表中选择一个模型，并在会话刷新或重新打开后保持选择。Embedding、Rerank、协作研究和 A2A 本轮继续使用现有默认配置。

## 接口契约

- `GET /api/model-provider` 在现有 Provider 响应中增加可选 `chatModels` 数组；未配置时保持原有 404 语义。
- `PUT /api/model-provider` 接受可选 `chatModels` 数组。服务端会去空格、去重、限制数量和长度，并确保 `chatModel` 在数组中。
- Agent 请求增加可选 `chat_model`。为空时使用 Provider 的默认 `chatModel`；非空时必须命中服务端配置的 `chatModels`，否则返回 400。
- 会话对象增加可选 `chatModel`；`PATCH /conversations/{id}` 接受可选 `chat_model`，与标题和置顶字段共用归属校验。

## 安全边界

- 浏览器只能提交模型标识，不能提交 Base URL、API Key 或任意 Provider 配置。
- 服务端对模型名称做长度、数量和 allowlist 校验；模型名称只作为已配置 Provider 的选择键。
- API 响应不返回密钥，日志不记录模型调用凭据。

## 验收标准

- 未传 `chat_model` 的旧请求行为不变。
- 选择已配置模型后，Agent 的工具调用使用该模型。
- 未配置模型、未知模型和跨知识库会话均被安全拒绝。
- 会话模型选择可以保存、读取，刷新后前端仍显示当前选择。
- 后端单元测试和前端生产构建通过；前端选择器有加载、空列表、错误和生成中禁用状态。

## 预计修改范围

- Go：模型 Provider、聊天运行时、Agent 请求/Handler、会话 Store、数据库迁移及对应测试。
- Vue：模型选项加载、会话模型状态、聊天头部选择器、请求参数和样式。
- 文档：README 配置说明和本规格。

## 暂不实现

- 多个独立 Provider 的管理页面。
- 每个会话独立的 Embedding/Rerank 模型。
- 模型自动路由、成本策略和深度思考开关。
