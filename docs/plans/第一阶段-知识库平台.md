# 第一阶段：知识库平台最小闭环

## 目标

独立重写一个参考 WeKnora 技术栈与工程形态的知识库问答平台。第一阶段交付可运行的最小前后端闭环；不直接复用上游源码。

本项目的长期编码标准是：Go 代码保持惯用、直白、适合初学者阅读，HTTP、业务、存储和后台调度职责清晰；不同频率的后台任务独立调度，并在交付时配套最小示例和调用链解释。

## 已确认的基础选择

- 后端使用 Go；前端遵循 WeKnora 的技术路线。
- 前端采用 Vue 3 + TypeScript + Vite，并使用 TDesign 作为基础组件库。
- 本地依赖通过 Docker Compose 管理。
- 默认接入兼容 OpenAI API 的外部模型，并预留 Ollama 适配层。
- 先以单个本地管理员模式运行，后续再补登录、工作区与权限。

## 已确认的实施决策

- 首版只支持 Markdown、TXT 与可提取文本的 PDF。
- PostgreSQL 启用 pgvector，同时保存应用数据、处理任务与文档向量。
- Docker Compose 只管理 PostgreSQL；Go 后端和 Vite 前端以本机开发模式启动。
- 原始文件存放在受 Git 忽略的本地数据目录。
- 文档处理使用数据库任务表和 Go worker，状态为待处理、处理中、成功或失败。
- 模型通过一套兼容 OpenAI API 的 Provider 配置接入，分别设置聊天模型与嵌入模型。
- 问答通过 SSE 流式返回；回答完成时展示引用来源。
- 模型密钥只保存在本地 `.env`，界面不回显明文。

- 已完成：共享模型 Client 的聊天调用能力与本地聊天测试接口；它使用已保存的 `chatModel`、安全 HTTP 限制和 `.env` 密钥调用 OpenAI 兼容的 `/chat/completions`。已完成单元验证；待填写真实密钥后手动验证远端模型连通性。
- 已完成：知识库、文档和文档处理任务的版本化 SQL 数据模型；它们依次关联、具有处理状态与索引，删除知识库时会级联清理对应的文档及任务记录。
- 已完成：`knowledgebase` Go 数据访问层与创建、查询、删除知识库接口；知识库名称、描述、结构化 JSON 输入与资源 ID 均已校验。
- 已完成：Markdown、TXT、PDF 的安全上传接口；源文件使用随机受控路径写入 `UPLOAD_DIR`，数据库事务同时创建文档和 `pending` 处理任务，失败时清理已写入的文件。
- 已完成：Worker 的安全任务领取与状态流转底座；使用 `FOR UPDATE SKIP LOCKED` 防止并发 Worker 重复领取任务，并更新 `pending → processing → succeeded/failed`。
- 已完成：TXT、Markdown 和常见文本型 PDF 的提取器，会从受控的本地存储路径读取非空文本，并可作为 Worker Processor 使用；损坏或无文本 PDF 会进入失败状态。
- 已完成：`document_chunks` 数据表、按段落优先切分且带重叠的切分器，以及将文档提取结果替换写入文本块的 Worker Processor。
- 已完成：将 TXT/Markdown/PDF 提取、切分、文本块写入装配到后端 Worker；服务启动后按 `WORKER_POLL_INTERVAL` 轮询 `pending` 任务并更新状态。
- 已完成：Worker 使用已有 Embedding Client 将每个文本块向量化并写入 pgvector；向量化失败会使任务进入 `failed`，文本块替换写入使用事务保证一致性。
- 已完成：知识库语义检索接口；它将用户问题向量化后按 pgvector 距离返回指定知识库内最相似的文本块。
- 已完成：非流式 RAG 问答接口；它将检索到的文本块作为受约束的 Chat 上下文，返回模型回答和来源。
- 已完成：后端 SSE 流式 RAG 接口；它按 `sources → delta → done` 事件顺序推送来源、模型增量和结束信号。
- 已完成：前端知识库工作台首版；支持知识库创建与切换、Markdown/TXT/文本型 PDF 上传、文档处理状态轮询、SSE 流式问答和引用展开。为支持状态刷新，新增 `GET /api/knowledge-bases/{id}/documents` 文档列表接口。
- 已完成：前端模型服务设置抽屉；支持读取、保存 Provider 的服务名称、Base URL、聊天模型和嵌入模型，并提供连接测试入口。API Key 不进入浏览器，只由后端从 `.env` 读取。
- 已完成：Worker 的 PDF 处理集成测试；使用真实 PDF 提取器、切分器和嵌入处理器验证任务领取、文本块写入与 `succeeded` 状态流转，不依赖真实 API Key。
- 已完成：扫描 PDF OCR 的最小接入骨架；通过 `pdftoppm` 将页面渲染为 JPEG，使用独立 `OCRProvider` 调用 OpenAI 兼容的视觉模型，并将按页 OCR 文本复用现有切块、向量化和任务状态链路。只有配置 `OCR_MODEL` 时才启用。
- 当前限制：Docker/PostgreSQL 未运行或模型密钥未配置时，前端会显示 API 错误提示；OCR 当前只对整份 PDF 无可提取文本时触发，混合型 PDF 的逐页分类、复杂版面和专用解析器仍未覆盖。
- 阶段结论：知识库上传、异步处理、向量检索、RAG/SSE 问答主链路已经达到第一阶段验收。OCR 只保留为一次可选的真实扫描 PDF 验证，不再作为进入下一阶段的阻塞条件。

## 实施顺序

### 1. 工程与本地运行底座

- 补齐后端、前端和 Docker Compose 的基础目录及开发配置。
- 启动 PostgreSQL、后端和前端开发服务。
- 保持健康检查可用。

验收：新环境按说明启动后，可打开前端并访问后端健康检查；数据库迁移可成功执行。

### 2. 基础数据与模型配置

- 接入 PostgreSQL 并建立迁移机制。
- 建立单管理员、模型配置和基础系统配置。
- 提供模型连通性检查与统一模型调用接口。

验收：可通过 `.env` 在本地配置一个兼容 OpenAI API 的模型，并完成聊天模型与嵌入模型的连通性验证。

### 3. 知识库与文件管理

- 创建、查看和删除知识库。
- 上传和管理基础文档。
- 以异步任务处理文档，并展示处理状态。
- 将原始文件写入本地数据卷。

验收：可在前端创建知识库、上传一份支持格式的文档，并看到明确的处理状态与结果。

### 4. 文档检索与 RAG 问答

- 将已处理文档切分、向量化并写入 pgvector。
- 按问题检索相关片段，组装模型上下文并生成回答。
- 以 SSE 流式展示回答，并在完成后展示引用来源。

验收：用户可针对已上传资料发起对话，获得基于资料的回答及可查看的引用。

### 5. 最小可用体验与交付验证

- 完善知识库、上传、处理状态和对话页面的基本交互。
- 补齐关键链路测试、错误提示、启动说明与示例配置。
- 使用 Docker Compose 完成一次从空环境到问答闭环的验证。

验收：按文档启动服务后，能完成“创建知识库 → 上传资料 → 等待处理 → 提问并查看引用”的完整流程。
